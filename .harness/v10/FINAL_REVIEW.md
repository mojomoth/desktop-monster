# Final evidence receipt

Host writes `RUN/reviews/final.json` after collecting the three actual independent reviews. This file is evidence, not an approval generated by the checker. Keep earlier attempts. Use `digest()` and `sha()` from `run.mjs`; use `artifactHash(path)` from `final-check.mjs` for all package entries. A directory hash covers sorted relative file SHA-256 values and symlink destinations without following symlinks. JSON is formatted with two spaces and one trailing newline before hashing.

```json
{
  "version": 10,
  "source": "CURRENT_DIGEST",
  "passed": true,
  "reviews": [
    {"scope":"core-host","reviewer":"/root/backend_v10","implementedBy":["/root","/root/equipment_economy"],"verdict":"approved","evidence":{"path":"REVIEW_FILE","sha256":"HASH"},"sourceHashes":{"REVIEWED_SOURCE_PATH":"HASH"}},
    {"scope":"backend","reviewer":"/root/sprite_qa","implementedBy":["/root/backend_v10"],"verdict":"approved","evidence":{"path":"REVIEW_FILE","sha256":"HASH"},"sourceHashes":{"REVIEWED_SOURCE_PATH":"HASH"}},
    {"scope":"visual","reviewer":"/root","implementedBy":["/root/sprite_qa"],"verdict":"approved","evidence":{"path":"REVIEW_FILE","sha256":"HASH"},"sourceHashes":{"REVIEWED_SOURCE_PATH":"HASH"}}
```

`sourceHashes` must cover the actual files read by each reviewer, including required critical scope files listed in `validateReviews`. Reviewers cannot approve their own implementation. The example labels/paths above are placeholders; all hashes must be calculated from the final, independently reviewed source/evidence. A performed external check requires an additional hashed `evidence` record. Unperformed external checks remain explicit limitations and do not silently become approvals.

`final-check.mjs RUN` checks current canonical gates and each latest AC/verified task (excluding its own V10-10 AC to avoid a cycle), re-derives balance reports from raw rows, verifies all 16 native scenarios/screenshots and matching final packages, verifies the five performance observations with `performance-report.mjs verify`, and enforces package version 0.10.0 and compiled-payload equality. It does not run new observations or issue reviews.

Installer verification also mounts the DMG read-only and compares its entire app tree with the verified macOS app, then uses the existing electron-builder 7zip tool to extract the NSIS installer and nested app archive and compare the entire Windows tree. Same-version stale installers cannot substitute for the measured unpacked apps. Extracted content is never executed. Temporary extraction directories are removed after the read-only image is detached; the final check returns the compared payload and installer hashes.

The native gallery receipt must be `RUN/native/gallery-final.json`, produced by `gallery.mjs`: 150 pages, 7,148 unique hero/item/pose/facing/theme samples, four overview PNGs, current generator/source/build hashes and the final package hash. Every PNG and overview membership is checked. The catalog is verified with `catalog.mjs verify`, which rebuilds the complete public JSON and Markdown from current core TypeScript.

Exploration and held-out balance receipts preserve separate source identities. A production change to the selected registered parameters is allowed only when `EXPLORATION/source-core/equipment.ts` matches the original equipment hash, every non-parameter byte remains equal after canonical substitution, other core modules are unchanged, and every measured compiled candidate matches current TypeScript transformed with that same registered candidate. Held-out source must match current source exactly. This exception does not permit new gameplay code or evaluation rules between exploration and validation.
