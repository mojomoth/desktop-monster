# v0.4 — 영웅을 키우고, 모습을 모으고, 파티를 비교하기

사용자 요구를 v4 구현/검증에 연결하는 참조 사양이다. 실제 결과는 테스트/세션 기록으로
확인한다. 아래 수치 중 경험적 재미 목표는 시뮬레이션·사람 관측 전까지 가설이다.
루트 `SPEC.md`의 기존 계약은 유지하고 v0.4에서 달라지는 동작을 이 문서에 명시한다.

## 영웅의 성장

실제 영웅 공격은 `src/core/hero.ts`의 `heroDamageForLevel`과 `heroAttackPower`를 사용한다.
기존 `damageForLevel`은 과거 계약/호환성을 위해 남아 있어도 실전 강화식과 혼동하지 않는다.

`D(L)=L+max(0,L−2)^2`: 레벨 1/2/5/10의 기본 피해는 1/2/14/74.
실전 비치명 피해는 `floor(D(L)×(1+souls)×(100+25×heroReincarnations)/100)`.
치명타/피버 등은 실제 엔진 적용 순서로 검증한다. 피해와 UI에 표시하는 값이 일치해야 한다.
일반적인 레벨업이 몬스터 HP 증가 속도에 밀리는지 5/15/30분 기준으로 비교한다.

## 영웅 환생과 도감

- 레벨 12부터 영웅 환생 선택을 열 수 있다. 기존 동료 환생과 구분되는 행동이다.
- **수락할 때만** 영웅 레벨/XP와 현재 몬스터를 처음으로 되돌린다. 돈과 동료는 보존한다.
- 영웅 환생 횟수 +1, 기존 영혼에 `max(1,floor(monsterIndex/8))`을 더한다.
  영구 공격력과 다음 외형 단계가 반복 성장의 보상이다.
- 수락 후 120초의 활성 엔진 휴식 시간을 둔다. 성숙한 동료 파티가 수초 만에 다시
  레벨 12를 찍어 환생을 연타하는 경우에도 선택 기회가 업무를 압도하지 않게 한다.
  무료 보류의 30초 재기회와 구분되며, 휴식 중에도 전투/성장은 진행한다.
- 10개 형태 계열 × 5개 시각 단계, 최소 50종 `h01..h50`. 기본 영웅 `h00`은 별도다.
- 각 형태는 이름/단계/속성/버프 종류가 고정이다. 환생이 진행될수록 최대 5단계까지 해금한다.
- 10계열은 검사/창술사/거너/성직자/도적/광전사/마법사/격투가/수호기사/소환사 순서다.
  기존 ID별 속성/버프/단계를 보존하며 직업 이름과 도트만 교체한다.
- 던전앤파이터의 직업별 무기와 의상을 참고하되, 기본 영웅 `h00`과 **같은 14×14 프레임과 SD 비율**을
  유지한 독자적인 도트다(사용자 최종 승인 규격, `docs/v0.4/HERO_REDESIGN.md`가 기준이다).
  대기 2장 + 공격 3장 = 모습당 5프레임, 모습당 7색 이내로 그린다.
  등급이 올라가도 신체·도트 크기를 키우지 않으며, 원본의 눈 위치·손 공격 궤적·발 접지를 그대로 유지한다.
- 5단계마다 헤어/머리 장비, 의상 재단, 무기 외곽이 달라야 한다. 팔레트 변경만으로 50종을 채우지 않는다.
  피부색과 눈 색도 모습마다 구분하며, 날개/후광/공중 장식과 몸에서 떨어진 장식은 사용하지 않는다.
  실제 400×260 필드, 96px 환생 카드, 64px PvP 목록에서 영웅 본체는 모두 56px(도트 1칸 = 4px)로
  그려지며, 이 크기에서 얼굴과 직업의 가독성을 비교한다.
- 획득한 외형과 roll은 저장된다. 중복 외형은 좋은 roll을 유지하고 다시 장착할 수 있다.

## 세 개의 제안

한 번에 서로 다른 외형 3개와 서로 다른 속성 3개를 보여준다. 이름, 도트 미리보기,
단계, 속성, 고정 버프의 적용 대상과 이번 roll 수치를 함께 표시한다.
최고 해금 단계에 미수집 외형이 남아 있는 동안에는 그 단계의 외형을 최소 하나 보장한다.
최고 단계를 모두 수집한 뒤에는 첫 후보도 전 단계의 미수집 외형으로 열려, 도감이
14종에서 멈추지 않고 계속 자란다. 세 후보 모두 가능한 범위에서 미수집 외형을 우선한다.

마음에 들지 않으면 무료 보류 또는 게임 내 골드 재굴림을 고른다.
보류는 진행을 리셋하지 않고 엔진이 진행하는 30초 뒤 새 기회를 허용한다.
이 30초는 앱이 실제로 진행하는 시간이며 종료/절전 중의 벽시계 경과로 앞당기지 않는다.
골드 비용은 `50+25×min(100,heroReincarnations)`이며 상한은 2,550골드다.
재굴림 전 비용을 확인할 수 있고 돈이 부족하면 차감/제안 변경이 없어야 한다.
현금 결제 기능은 이 설계에 포함하지 않는다.

제안 ID와 roll을 저장하고 창 재개로 다시 뽑지 않는다. `offerSerial`로 오래된 클릭과
중복 IPC가 다른 제안을 고르거나 추가 지출을 만들지 못하게 한다.
무료 보류, 수락, 재굴림을 동일 seed에서 비교하여 무료 경로가 실용적인지 확인한다.

## 속성·버프의 고정 정체성과 랜덤 수치

속성은 기존 fire/water/wind/earth/dark 5종이다. 같은 외형은 언제나 같은 속성/버프를 갖는다.
roll은 균등 정수 10..25이며 획득/제안 시 주입된 RNG로만 결정한다.
각 단계에서 첫 5개 계열은 일치 속성 동료 +2×roll%, 다음 5개는 전체 동료 +roll%다.
수치 예산은 시각 단계에 따라 증가하지 않는다. 외형과 취향을 낮은 전투력으로 처벌하지 않는다.
PvE 자동 파티 선택/동료 공격과 PvP 파티 전력/재생에 같은 버프 함수를 적용한다.
입력 payload의 임의 속성/버프 정의는 신뢰하지 않고 form ID로 고정 정체성을 구한다.

## PvP는 상대 목록에서 시작

검색 입력 없이 상대 목록을 표시하고 상대를 고르면 기존 사전보기/파티 선택/결정적 전투
재생으로 이어진다. 목록은 상대 영웅 외형, 실제 배치된 동료 최대 5마리, 승/패 전적을 보여준다.
상대가 없거나 서버가 잠든 경우 empty/loading/offline 상태와 재시도를 제공한다.

전적은 서버가 확정한 배틀 결과에서 갱신하고 클라이언트 업로드 숫자로 덮어쓰지 않는다.
이전 플레이어 데이터에 영웅/전적이 없어도 기본 영웅/0전적으로 표시하고 PvP가 작동한다.
PvP 판정과 roster 이동은 기존 서버 권한을 유지한다. 상대 목록과 사전보기/전투의
파티 구성이 일치하는지, 오래된 상대 데이터가 오류로 처리되는지 검증한다.

## 필수 검증 연결

| 요구 | 실행 근거/관측 |
|---|---|
| 하네스 4역할과 비평가 veto | `node .harness/v4/loop/fun.mjs selftest` |
| 실제 영웅 성장/환생/저장/roll/중복 방어 | `npx vitest run tests/hero.test.ts`와 전체 앱 게이트 |
| 50개 도트/단계/미리보기 | `npx vitest run tests/heroForms.test.ts`; 50종 전체 시트와 필드 사람 비교 |
| PvP 목록/영웅/파티/전적 | 서버·클라이언트 테스트를 포함한 `npm test`; 목록에서 실제 수동 흐름 |
| 5/15/30분 재미 가설 | seeded 엔진 실행 로그, 9개 시나리오 보고서, 이후 사람 관찰 기록 |
| 기존 저장과 기능 회귀 | `npm test && npm run lint && npm run typecheck` |

CLI selftest의 합성 보고서는 게임 밸런스 근거가 아니다. 자동 테스트의 통과도
50개 외형이 사람 눈에 모두 독창적이고 멋지다는 증거가 아니다.
native smoke/package/배포와 사람 관측은 `RELEASE_CHECKLIST.md`로 인계한다.
