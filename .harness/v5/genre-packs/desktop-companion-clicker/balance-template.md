# 숫자로 확인할 재미 가설

수치는 DesMon의 초기 가설이다. 다른 게임에서 검증된 최적값이라고 주장하지 않는다.
실제 채택값은 `reference/GAME_DESIGN_V5.md`와 구현의 export를 확인한다.
범위 변경은 결과를 본 뒤 조용히 맞추지 말고 디자이너/비평가 재검토에 남긴다.

## 프로필과 표본

| 프로필 | 주입 입력/시간 | 분리할 초기 상태 |
|---|---|---|
| active | 초당 2회 입력, 1000 ms 엔진 tick | 새 게임; 동료 보유 복귀 |
| idle | 최초 120초는 초당 2회, 이후 입력 0회; 1000 ms tick | warm-idle: 초기 활동 후 방치; 동료 유무 기록 |
| intermittent | 최초 120초 활동 후 매 60초 중 15초만 초당 2회; 1000 ms tick | 간헐 입력; 동료 보유 복귀도 별도 검사 |

5/15/30분의 가상 엔진 시간을 실행한다. 실제 대기를 하지 않는다. 최소 100개 독립 seed를
고정하고 이전/수정 버전에 같은 seed 집합을 사용한다. `seed=404..503` 같은 집합,
seed 생성법, 세이브 fixture, 행동 정책, 코드/빌드를 보고서에 적는다.
초당 2회는 검사 프로필이며 실제 사용자 타이핑 속도나 유지율 추정이 아니다.
`tests/balance.test.ts`의 현재 회귀 프로필과 일치한다. 순수 방치(시작부터 입력0/동료0)는
별도의 정지 기준으로 기록하고 warm-idle 결과를 순수 방치 성장으로 설명하지 않는다.

## 최초 목표

| 지표 | 초기 목표 | 실패 시 검토 |
|---|---|---|
| lv1→10 비치명 영웅 공격 | lv1=1, lv10=74인 강화 성장식; 실제 배율은 별도 표시 | 레벨 변화가 damage 이벤트에 반영되는가 |
| 무료 보류 후 재기회 | 활성 엔진 시간 30초 이내 | 벽시계/재접속으로 지연되거나 강제로 열린 창이 있는가 |
| 수락 후 다음 환생까지 휴식 | 활성 엔진 시간 최소 120초 | 성숙 파티가 수초 간격으로 선택을 연타하게 되는가 |
| 3개 선택지 내 ID/속성 중복 | 0 | 표본만 보지 말고 invariant 검사 |
| 최고 해금 외형 단계의 포함 | 그 단계에 미수집 일반 영웅이 남아 있는 동안 100% | 랜덤 불운으로 시각 진화가 멈추는가 |
| 미수집 외형이 첫 후보에 오는 비율 | 일반 도감 미완성 구간 100% | 최고 단계를 다 모은 뒤 도감이 멈추는가 |
| 외형 버프 roll | 정수 10–25 범위, 단계별 같은 예산 | 높은 외형만 수치까지 우월한가 |
| 재로드에 의한 추가 뽑기 | 0 | pending 제안과 roll이 저장되는가 |
| 새 게임 첫 환생 도달 | active 프로필 5분 이내를 탐색 목표로 설정 | 5분에도 기회가 없거나 수초 반복이면 조정 |
| 자동 포커스 강탈/강제 선택 | 0회 | 실제 macOS에서 별도 확인 |

첫 환생 시간/골드 경제/장기 DPS는 시뮬레이션 전 가설이며 통과 결과가 아니다.
순수 방치 새 게임은 자동 공격 동료가 없으므로 첫 환생 도달 목표를 적용하지 않는다.
설계상 상수(invariant)와 표본 분포를 구분해 보고한다.

## 계산

후보 성장식: `D(L)=L+max(0,L−2)^2`. 예: L=5 → 14, L=10 → 74.
비치명 기본 공격에 영혼/영웅 환생의 영구 배율을 곱하고 치명타/피버 적용을 분리한다.
예상 영웅 DPS는 `입력/초 × 비치명 피해 × (1+critChance×(critMult−1))`다.
피버와 속성에 따른 실제 값은 엔진 이벤트를 합산하며 이 근사식과 차이를 설명한다.

`TTK ≈ HP / (heroDPS + partyDPS)`를 기준으로 실제 처치 간격을 비교한다.
증가 체력/자동 파티 선택/치명타 때문에 평균만으로 긴 정체가 가려질 수 있다.
각 세션의 최장 무처치 구간과 영웅 피해 기여도도 기록한다.

roll이 정수 10..25 균등이라면 이론 평균은 17.5다. 전체 파티 버프는 평균 +17.5%,
속성 일치 버프는 그 동료에 평균 +35%다. 같은 원래 전투력의 동료 5마리라면
속성 일치 동료 2마리일 때 전체 기여 +14%, 3마리일 때 +21%로 선택의 경계가 생긴다.
실제 비균등 전투력/속성 상대/공격 순서의 결과는 모든 상대 속성에서 별도로 계산한다.

골드 경제는 `잔액(t)=초기 잔액+처치 수입−재굴림−영구 훈련/탐색 미끼 지출`이다.
`재굴림 회복 시간=재굴림 비용/분당 골드 수입`; 수입 0이면 무한대/도달 불가로 기록한다.
0이나 NaN으로 덮지 않는다. 수락/보류/재굴림의 동일 seed 실험에서
환생 횟수, 고유 외형 수, 보유 골드, 동료 성장을 함께 비교한다.

## 결과 양식

실행 명령, 코드 버전, seed 집합, 표본 수, 입력 정책, 시작 세이브를 먼저 기록한다.

| metric | unit | before p10/p50/p90 | after p10/p50/p90 | target min/max | 판단 |
|---|---|---|---|---|---|
| 첫 환생 시간 | seconds | 실행 후 기입 | 실행 후 기입 | 최초 가설 | pass/revise |
| 최장 무처치 구간 | seconds | 실행 후 기입 | 실행 후 기입 | 사전 선언 | pass/revise |
| 영웅 피해 비중 | percent | 실행 후 기입 | 실행 후 기입 | 사전 선언 | pass/revise |
| 재굴림 회복 시간 | minutes | 실행 후 기입 | 실행 후 기입 | 사전 선언 | pass/revise |
| 수집 고유 외형 | count | 실행 후 기입 | 실행 후 기입 | 사전 선언 | pass/revise |

백분위는 정렬한 표본의 `floor((n−1)×q)` 위치처럼 계산법을 명시한다.
미도달/불가능 표본 수와 최대값도 함께 보고한다. 미도달 표본을 제외한 p90만으로 통과하지 않는다.
CLI의 `metrics`에는 유한한 실제 관측값을 제출하고, 미도달은 finding 및 별도 도달률 지표로 표시한다.
원시 CSV/JSON과 로그를 `evidence`에 첨부한다. 골드 유입/유출/무료 경로는 `economy`에도 요약한다.

## 악용/경계 사례

선택 버튼 중복 클릭, 골드 부족, 최대 정수/잘못된 roll, 존재하지 않는 form ID,
레벨 직전/직후, 보류 중 재로드, 상위 랭크 전체 수집, 동료 0/최대 슬롯,
이전 버전 세이브, 상대 목록 stale/empty/offline, 목록과 전투 파티 차이를 검사한다.
핵심 로직은 Vitest에서 seeded RNG와 주입 clock으로 검증한다. 네트워크/실시간 타이머를 사용하지 않는다.

## V5 변경 계약

첫 환생 이후 레벨 문턱, 레어 스폰 RNG와 반복 선택이 추가되므로 V4의 30분 정확한
처치 수/15회 환생/15개 고유 형태 기대값은 V5 수치 목표가 아니다. V4 기준 파일과 비교하되,
V5의 사전 허용 구간은 GAME_DESIGN_V5.md에 선언하고 새 결정적 검사로 대체한다.
기존 경계/방어/무료 경로 검사는 계속 실행한다. 결과에 맞춰 임계값을 느슨하게 만들지 않는다.

골드 정책은 무료/훈련 우선/미끼 우선/재굴림을 같은 seed로 비교한다. 유입-지출=잔액,
미끼 사용 잔여량, 훈련 전후 실제 damage 이벤트, 잠금 레어 노출0, 보장 상한12를 검사한다.
반복 환생은 기본 roll이 하락해도 best roll+stack이 반드시 오르는지 검증한다.
