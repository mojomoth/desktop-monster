# 다섯 분 안에 검증 가능한 선택으로 좁히기

## 핵심 질문

1. 사용자가 문서/코딩/웹 작업을 계속하면서 다음에 잠깐 보고 싶어질 이유는 무엇인가?
   현재 보상 간격/기여도 데이터를 하나 붙여 답한다.
2. 영웅을 10레벨 올렸을 때 어떤 동작이나 결과가 달라지는가?
   피해 숫자, 처치 속도, 다음 환생 진행도를 각각 설명한다.
3. 외형 3개 중 선택을 바꾸는 이유가 외형 취향, 속성 파티, roll 중 무엇인가?
   서로 다른 파티 세 개를 만들어 최선의 선택이 달라지는지 공격한다.
4. 3개 모두 싫을 때 무료 보류가 실용적인가? 보류 후 다음 행동까지 얼마인가?
   기다림/골드 지출 각각을 고를 이유와 누적 비용을 적는다.
5. PvP 목록에서 상대 영웅과 몬스터/전적을 보고 5초 안에 도전 대상을 고를 수 있는가?
   실제 플레이어 관측 없이 5초 목표를 달성했다고 선언하지 않는다.

## 장르 제약

- 매 분 새 모달을 띄울 수 없다면 무엇으로 목표와 발견을 표현할 것인가?
- 입력량이 거의 없는 날에도 이미 모은 동료가 가치를 갖는가?
- 모든 사람이 가장 강한 외형 하나를 입는다면 70종 디자인이 어떤 의미를 남기는가?
- 골드가 바닥났고 모든 제안이 마음에 들지 않아도 계속할 이유가 있는가?
- 색을 제거한 실루엣만 봐도 상위 진화가 구별되는가?
- 시스템을 하나 더 넣지 않고 기존 보상/발견/표시 순서를 바꾸면 해결되는가?

## 세 가지 방향을 먼저 비교

| 방향 | 제안할 작은 변경 | 줄여야 할 비용 |
|---|---|---|
| 캐릭터 동반자 | 영웅 실루엣/승리 반응/선택 미리보기의 존재감 | 화면 점유/강제 주목/시각 소음 |
| 방치 성장 | 레벨 피해/환생 회복/동료 지원의 짧은 피드백 | 정체 시간/반복 클릭 요구 |
| 수집 빌드 | 미수집 제안/속성별 동료 버프/상대 목록 비교 | 가짜 선택/숫자 최고 강요/새 규칙 수 |

최소 3개, 최대 5개 대안은 각기 다른 tradeoff를 가져야 한다.
동일 기획의 숫자만 10/20/30으로 바꾼 세 안은 구조적 대안이 아니다.
조건부 레어 영웅/몬스터, 중복 환생 성장, 골드의 여러 용도, 도감/히스토리는 V5 필수 범위다.
실제 생활 시간 접속을 강제하거나 도감 조건을 유료로만 공개하는 방식은 피한다.

## 비교표에서 JSON으로

각 대안에 이름, 현재 문제의 근거, 행동 변화, 구현 파일, 측정 지표, 허용 범위,
업무 방해 비용, 무료 경로, 삭제하거나 재사용하는 기능을 기록한다.
현재 사용자 필수 요구를 충족하고 가장 적은 변경으로 검증 가능한 하나를 `choice`로 고른다.
다음 비평가는 선택한 안의 최악의 파티/골드/진행 상태를 찾아 반례를 만든다.

차별화는 다른 작품의 시스템 수를 따라가는 방식으로 평가하지 않는다.
DesMon에서만 가능한 조합인 평소 입력의 영웅 공격, 영구 외형, 동료 속성 파티,
잠깐 보는 비동기 대결이 같은 화면에서 자연스럽게 이해되는지 검증한다.
