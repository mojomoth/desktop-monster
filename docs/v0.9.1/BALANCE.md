# v0.9.1 금화 PvP 밸런스

수치는 [CONTRACT.md](CONTRACT.md)와 동일하다. 최초 측정 전에 정책을 고정했으며 결과에 맞춰 변경하지 않았다. 이 문서는 경제 측정 근거이며 최종 출시 판정은 별도다.

## 변경과 보호 정책

기존 PvP는 공격자가 이기면 확률적으로 동료를 가져갔다. 새 전투는 동료를 이동시키지 않고, 공격·방어 중 어느 쪽이든 패자가 낸 금화를 승자가 같은 양만큼 받는다. 기존에 확정된 동료 이동·회수 영수증은 복구용으로 유지한다.

금화 잔액을 `B`, 당일 서버 관측 최고 잔액을 `P`라고 할 때 다음을 적용한다. 나눗셈은 내림한다.

| 항목 | 확정 정책 |
| --- | --- |
| 보호 잔고 | 75G |
| 1회 금액 | 패자 잔액의 5%, 최대 75G |
| 일일 손실 한도 | `min(250, floor(P / 10))`에서 당일 누적 손실 차감 |
| 일일 획득 한도 | 250G에서 당일 누적 획득 차감 |
| 공격자가 감수하는 금액 | `min(floor(B / 20), 75, max(0, B − 75), 당일 손실 잔여)` |
| 동일 상대 보호 | 두 계정의 공격 방향과 관계없이 실제 금화 이동 후 60분 |
| 전투 간격 | 공격자 60초, 방어자도 전체 공격자로부터 60초 |
| 방어 수신함 | 미수신 확인 이벤트 5개면 새 공격 거절 |

최종 금액은 패자 기준 금액·보호 잔고 초과분·손실 잔여·승자 획득 잔여·승자 정수 표현 여유·공격자가 감수하는 금액의 최솟값이다. 따라서 잔액을 낮추거나 손실 한도를 소진한 공격자가 큰 보상만 얻는 전략을 제한한다. 동일 상대 보호 중에는 전투와 전적은 남지만 금화는 0G다. 봇·잔고 부족·보호 한도에서도 최소 보상을 만들지 않는다.

75G는 첫 훈련 또는 첫 미끼 구매비용이다. 첫 영웅 재굴림은 50G다. 보호 잔고는 약탈이 기본 구매 한 번까지 없애지 않도록 정했다. 오프라인에서 이미 소비한 금화의 미정산액까지 없애는 규칙은 아니다.

일일 한도는 UTC 날짜 기준이며 이동하는 24시간 창이 아니다. `P`는 그날 서버에 반영된 잔액과 PvP 획득 중 최고값이다. 금화를 소비·초기화해도 같은 날의 최고값과 누적 손실은 내려가지 않는다. 새 수입으로 최고값이 올라가면 손실 한도도 최대 250G까지 늘어난다. 자정 전후에는 각각의 날짜 한도가 적용된다.

## 측정 결과

seed `40001..40100`, 100ms 간격으로 가상 30분을 실행했다. 활동 정책은 새 게임에서 초당 2회 입력한다. 동료 방치 정책은 기본 동료 5마리로 시작해 입력하지 않는다. 두 정책 모두 구매·환생 선택·동료 관리를 하지 않는다.

| 정책, 각 100 seed | 30분 금화 p10 / p50 / p90 | 첫 약탈액 p10 / p50 / p90 | 첫 약탈액 최솟값 / 최댓값 |
| --- | --- | --- | --- |
| 활동 | 980 / 1,178 / 1,545G | 49 / 58 / 75G | 49 / 75G |
| 동료 방치 | 244 / 359 / 455G | 12 / 17 / 22G | 12 / 28G |

첫 약탈액은 양쪽 모두 해당 seed의 30분 잔액을 가진 합성 상대와의 첫 승리를 가정한다. 실제 매칭 승률이나 상대 분포를 예측한 수치가 아니다. 중앙값 기준 첫 약탈은 그 30분 동안의 평균 수입 약 1.5분(활동), 1.4분(방치)에 해당한다. 최고 잔액이 그대로라면 일일 손실 상한은 각각 117G와 35G다.

원시 자료 **1,400행**은 다음으로 구성된다. 같은 seed를 여러 정책에서 재사용하며 독립 플레이 세션 1,400회로 해석하지 않는다.

- **200행:** 두 정책 × 100 seed의 변경 전·후 PvE 비교. 전투 이벤트, RNG 사용, 체크포인트와 최종 게임 상태가 일치했다. 비교에서 제외한 필드는 새 금화 원장 기준값·부채뿐이다.
- **1,200행:** 두 잔액 정책 × 100 seed × 6개 경제 시나리오. 공격 승리, 방어 승리, 같은 상대 반복, 상대를 바꾸는 획득, 여러 공격자로부터의 손실, 오프라인 소비·복원을 검사했다.
- 경제 시나리오는 생산 `raidGold` 함수를 호출한다. 전체 잔액과 누적 순변동 보존, 회당·일일 한도, 방향을 바꾼 동일 상대 보호가 통과했다. 부채 시나리오는 실제 코어의 후속 아이템 금화로 상환했고, 같은 백업을 반복 복원해도 정산 결과가 같았다.

서버 CAS·동시 요청·영수증 재시도·방어 수신함·ACK 경계는 별도 HTTP handler 단위 테스트에서 검사한다. 1,400행 측정을 실제 네트워크 전투나 Electron 실행으로 표현하지 않는다.

## 회계와 한계

금화 PvP 자체는 통화를 발행하지 않는다. 서버가 양쪽의 동일 금액 증감·전적·방어 이벤트·영수증을 한 거래로 저장한다. 로컬에서는 `coins − debt + (serverNet − saveAppliedNet)`을 반영하며, 부족분은 이후 획득에서 상계한다. 차감할 잔고가 없다는 이유로 부족분을 버리지 않는다. 따라서 오프라인 소비와 응답 재시도가 승자에게 새 금화를 만들지 않는다.

PvE 수입과 로컬 소비는 여전히 클라이언트가 보고한다. 임의 세이브 편집, 여러 계정의 공모, 모든 구클라이언트를 통제하는 서버 경제를 구현했다고 주장하지 않는다. 순수 신규 방치, 30분 이후의 소비·환생 정책, 사람의 재미와 업무 방해는 이번 측정으로 판정하지 않았다.

같은 DB를 사용하는 구서비스가 계속 실행되면 구코드가 동료 약탈을 만들 수 있다. 운영 출시는 구서비스 PvP 중지 또는 함께 업데이트하는 절차가 필요하다. 운영 배포·실제 계정 전투·Windows 실기기·Steam 검증은 이 경제 측정의 통과 범위가 아니다.
