# v0.9.1 — 금화 PvP와 방어 전투

## 전투와 금화

새 PvP에서는 동료가 이동하지 않는다. 승자가 패자의 금화를 가져오며 공격자도 패배하면 금화를 잃는다. 금액은 패자 잔액의 5%, 75G, 잔액−75G, 당일 손실 잔여, 승자 획득 잔여 및 표현 가능한 잔고 여유의 최솟값이다. 공격자가 실제 잃을 수 있는 동일 공식의 금액을 추가 상한으로 적용한다.

- 보호 잔고 75G, 1회 최대 75G.
- UTC일 손실 한도: 당일 관측 최고 잔액의 10%, 최대 250G. 획득 한도 250G.
- 동일 두 계정은 방향과 관계없이 60분에 1회 금화 이동. 보호 중 전투는 0G.
- 기존 공격 쿨다운 60초. 방어자도 전체 공격자로부터 60초 간격으로만 전투를 받는다.
- 봇·보호 한도·잔고 부족에서 보상을 생성하지 않는다.
- 기존 확정 동료 이동 영수증과 회수는 복구 전용으로 유지한다. 새 동료 약탈은 생성하지 않는다.

## 정산과 복구

서버는 금화 이동·전적·방어 이벤트를 한 transaction에 기록한다. 금화 스냅샷도 revision CAS를 사용하며 성공할 때마다 증가한다. 누적 순변동 net은 부호 있는 정수 문자열이며 revision과 별개다. 클라이언트는 `coins − pvpGoldDebt + (serverNet − pvpGoldNet)`을 원자 반영한다. 오프라인에서 이미 사용한 차감분은 이후 획득 금화로 정산한다. 구매/XP/발견 보상으로 세지 않는다.

세이브 version 3을 유지하고 금화 기준값과 미정산액을 추가한다. 백업에는 당시 기준값을 보존하며 복원 시 최신 서버 기준으로 조정한다. 초기화는 미정산액과 온라인 기준·이벤트 진행을 되돌리지 않는다. 표현 범위를 넘는 양수 정산은 버리지 않고 보류한다. 악의적인 로컬 세이브 편집까지 막는 서버 경제로 주장하지 않는다.

새 전투 요청은 `mode: gold-v1`을 명시한다. 구서버에서는 안전하게 업데이트 필요를 알리고, 계정 자동 재등록으로 우회하지 않는다.

## 방어 수신과 재생

알림 권한과 독립된 주기 조회로 방어 이벤트를 받는다. 서버 미수신 확인 이벤트는 최대 5개이며 가득 차면 새 공격을 거절한다. main은 정산·대기열을 디스크에 저장한 뒤 서버 수신 확인을 보낸다. 재생 완료 확인은 별도이며 재시작 시 미완료 장면을 다시 재생해도 금화는 중복 반영하지 않는다.

당시 양쪽 파티·영웅·타격 기록을 사용한다. 방어 화면에서는 A/D를 바꾸어 내 파티가 왼쪽이 되며 ID나 피해량은 바꾸지 않는다. 한 장면은 최대 12초, 순서대로 재생한다. 최대 5건 오프라인 대기열은 1분 이내다.

재생 중 사냥 엔진·몬스터 HP/단계·피버·예약 공격·드롭/필드 연출을 함께 멈춘다. 입력은 버리며 종료 후 같은 엔진과 사냥 상태를 재개한다. 필드 상태줄은 전투 내내 `PvP 발생 · 상대 000와 전투 중`을 표시한다. 재시작은 기존 세이브가 표현하는 사냥 상태로 복귀하며 저장하지 않던 일시적 입자까지 디스크 복구한다고 주장하지 않는다.

## 검증과 출시 구분

Designer·Critic·Balance·Host의 독립 검토와 결정적 100 seed 이상 측정을 남긴다. 중복·응답 유실·동시 공격·복원·오프라인 소비·화면 중단/재개를 검사하고 실제 격리 Electron에서 양쪽 흐름을 확인한다. 정확한 전역 게이트는 `npm test && npm run lint && npm run typecheck`다.

현재 Windows 실기기, Steam AppID, 운영 서버 및 구서비스의 동시 전환은 별도 대기다. 코드 구현·자동 검증·배포 가능 여부를 구분해 보고한다.
