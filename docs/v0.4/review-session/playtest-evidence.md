## 프로필과 시작 상태

`tests/balance.test.ts`의 실제 엔진과 `mulberry32(1..100)`, 1000ms tick을 사용한다.
300개의 서로 다른 프로필/seed 궤적에서 5/15/30분을 관측한 900행이다.
모든 궤적은 새 게임 Lv1, 영혼/골드/동료 0에서 시작하며 첫 120초는 초당 두 번 입력한다.

- active: 이후에도 초당 두 번 입력.
- idle: 이후 공격 입력 0. 아래 표에서는 **warm-idle**로 부른다.
- intermittent: 이후 매 60초 중 15초만 초당 두 번 입력.

**세 프로필 모두 기회가 오면 에이전트가 제안을 열고 첫 후보를 즉시 수락한다.**
warm-idle에도 이 메뉴 행동은 존재한다. 따라서 공격 입력 없이 동료가 기회를 준비할 수
있다는 관측이며, 사람이 완전히 떠난 동안 14번 환생했다고 해석하면 안 된다.
골드 재굴림, 보류, 동료 관리는 이 100 seed 정책에서 하지 않는다. 그 분기들은 별도
결정적 기능 테스트로만 확인했다. 실제 업무 입력 빈도와 2회/초를 동일시하지 않는다.

## 9개 관측

모든 행은 해당 프로필의 seed 1..100이다. 숫자는 달리 표시하지 않으면 중앙값이다.
첫 기회는 공통 온보딩 때문에 모든 행에서 100/100 도달하며 p10/p50/p90=76/79/81초다.

|---|---|---:|---:|---:|---:|---:|

5분에는 세 프로필 모두 처음 두 번의 외형 선택을 받았다. 15분에는 모두 중앙값에서
새 형태 7종을 모았고, 30분에도 처치와 영구 성장은 이어졌다. 활동 입력은 방치보다
처치·골드를 늘리지만 120초 수락 후 휴식 때문에 환생 빈도만 무한히 높이지 않는다.
기회가 표시되었다는 사실로 사용자가 알아보거나 기뻐했다고 추론하지 않는다.

## 분리한 경계/복귀 조건

순수 새 게임 방치는 별도로 직접 확인했다. seed1, `createEngine(null, mulberry32(1))`,
공격/메뉴 행동 없이 `tick(1000)`을 1800번 호출했다. 5/15/30분 모두 Lv1, 처치0,
동료0, hero 없음이었다. 이것은 자동 공격 수단이 없는 의도된 정지 기준이며
warm-idle의 성공 자료로 섞지 않았다. 재현은 설치된 esbuild로 이 작은 TypeScript
진입점을 임시 CommonJS로 묶어 Node로 실행했으며, 새 의존성이나 저장 파일을 만들지 않았다.

```ts
import { createEngine, mulberry32 } from './src/core/index.js';
const engine = createEngine(null, mulberry32(1));
for (let second = 1; second <= 1800; second++) {
  engine.tick(1000);
  if ([300, 900, 1800].includes(second)) {
    const state = engine.getState();
    console.log(second / 60, state.level, state.killCount, state.companions.length, state.hero);
  }
}
```

동료 보유 복귀는 `critic-evidence.md`의 별도 seed12345 trace를 읽었다.
Lv12와 bossIndex80/level10/stars3 동료5마리에서 0입력 및 초당2회 모두 30분16회
(시작시 1회 포함), 간격120초였다. 0입력 기록의 5/15/30분 누적은 3/8/16회다.
이는 강한 복귀 파티의 연타 악용 반례이며 새 게임 100 seed와 같은 분포가 아니다.
복귀 intermittent 100 seed나 모든 실제 플레이어 세이브를 검증했다고 주장하지 않는다.

## 외형·선택·대전의 실제 연결

50종 카탈로그와 50개 도트 ID가 일치한다. 각 32×32 도트는 대기2/공격3프레임을 갖고,
50개 무채색 실루엣이 서로 다르며 계열별 단계가 오를 때 장비 면적이 늘어난다.
`hero-gallery.html`은 게임 코드에서 만든 독립 실행 도감이다. 내장 스크립트를 로컬에서
실행하여 50개 canvas와 대기/공격 표시를 확인했고, 원본 도트로 만든 로컬 래스터 시트를
점검했다. 이것은 코드와 에이전트의 시각 검사다. 사람이 50종을 모두 개성 있고 더
멋지다고 평가했는지는 미확인이다.

실제 `createGame`을 기록용 canvas로 그린 초기 h01 필드, 신화 h41 필드,
h41 대 h50 PvP, h41 공격을 로컬 래스터로 점검했다. 발은 같은 지면에 놓이고,
양쪽 몸통은 구분된다. 무기 일부의 중앙 겹침은 보이지만 몸통을 가리지는 않았다.
발견했던 떠 있는 손잡이, 낮은 단계의 HUD 빈 간격, 검 안쪽의 검격은 수정 후 확인했다.
화면 회귀는 초기/신화/기본 영웅의 실제 XP bar 위치, 공격 중 고정된 HUD,
진화된 검끝 밖의 slash와 PvP에서 slash 숨김을 검사한다. macOS overlay를 연 것은 아니다.

메뉴 실제 바인딩 테스트는 다음을 확인한다.

- 세 선택 카드 모두 도트 픽셀이 있고 버프 퍼센트가 표시되며, 선택/보류가 올바른 행동을 보낸다.
- 숫자만 바뀌는 자동 저장에는 영웅 제어와 도감 DOM을 유지한다. 확장된 메뉴 검사가
  같은 DOM 참조와 열린 도감 disclosure를 확인한다. native 키보드 포커스 체감은 별도다.
- `hero.test.ts`에서 골드 부족, 재로드 후 같은 제안/roll, 보류 후 30초 재기회,
  중복 offerSerial 지출 거부와 중복 외형의 최고 roll 보존을 확인한다.
- 상대 목록에 영웅 도트, 실제 파티 미니어처, `8승 2패`가 표시되고, 선택한 playerId로
  사전보기를 요청한다. 검색/임의 상대 매치가 자동으로 시작되지 않는다.
- 비어 있거나 실패한 상대 목록은 안내/재시도를 제공한다. 기존 테스트는 수동 파티와
  전투 결과/재생 전달도 확인한다. 실제 서버의 최신 데이터나 네트워크 지연은 이 검사가 아니다.
- 전문/전체 버프는 실제 피해·서버 판정에 반영되며 높은 시각 단계라는 이유만으로
  버프 예산이 더 크지 않다. 플레이어가 이를 이해하고 선택을 바꾸는지는 미확인이다.

## 남은 관측과 다음 검증

**PT1 — 동료 포화.** 동료 관리 없는 active는 15분4/100, 30분100/100이 30슬롯에
닿는다. intermittent도 30분99/100이다. 포화 후 새 포획이 멈추므로 다음 발견 보상이
줄어든다. 현재 메뉴의 `동료 30/30` 안내와 기존 Consume/Fuse/Sacrifice가 공간 확보
경로를 제시한다. 안내를 사용자가 보고 실제로 관리하는지는 사람 세션에서 기록해야 한다.
보관함 안내가 포화 자체를 없앤 것으로 평가하지 않는다.

**PT2 — 방치의 느린 꼬리.** warm-idle 30분 환생 p10/p50/p90는4/14/15이고,
최장 무처치 구간 p90은207초다. 최악 seed68은414초 정체와 환생2회/동료2마리,
seed84는405초 정체와 환생2회/동료1마리였다. 처음부터 불가능한 표본을 뺀 결과가 아니다.
현재 명시한 active 첫 기회 목표는 위반하지 않지만, 방치 보상의 수용도를 중앙값만으로
설명할 수 없다. 실제 사용자의 업무 복귀 시 반응과 재개 행동을 관찰한 후 조정할 항목이다.

**PT3 — 첫 칸 자동 선택의 14종 정체.** 최고 단계가 보장되는 첫 후보만 고르면
초기4단계에서 각1종과 신화10종, 총14종에서 중복이 시작된다. 이는 정책의 한계이며
도감 전체의 하드캡이 아니다. 두 번째/세 번째의 낮은 단계 미수집 후보를 고를 수 있고,
최상위 해금 상태 1000제안/3000roll 검사에서 전체50종이 등장했다.
사람이 낮은 단계도 같은 버프 예산을 갖는다는 점을 이해하고 나머지를 고르는지 관찰한다.

**PT4 — 행동 측정 범위.** 100 seed는 골드 지출/보류/취향 판단/비교 시간/업무 복귀를
측정하지 않았으며 warm-idle도 메뉴 선택은 자동 수행한다. 실제 재굴림 선호도, 골드 가격의
적절함, 영웅과 동료의 피해 기여 비율, 사용자가 느끼는 선택 부담은 여기서 결론낼 수 없다.
이번 판정은 기능/시뮬레이션 통과이지 무인 방치나 인간의 재미 통과가 아니다.

`humanChecks=PENDING`: 외형 구분과 단계별 선호, 세 카드의 선택 이해/비교 시간,
골드 부족/보류 후 자발적 복귀, 14종 이후 미수집 선택, 포화 안내 후 동료 관리,
긴 방치 구간 수용도, 5/15/30분 실제 업무 중 중단 횟수, 영웅 공유/애착 행동.

`nativeChecks=PENDING`: macOS 실제 접근성 권한/전역 입력, 포커스/가림/이동/소리,
실제 2× overlay와 여러 디스플레이, 실제 PvP 서버 목록/지연/재생. Electron smoke,
패키징 및 배포 확인은 별도 릴리스 체크리스트로 인계한다.
