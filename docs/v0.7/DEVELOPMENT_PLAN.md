# DesMon v0.7 개발 계약

승인 범위: v7 하네스 구성과 기존 v0.6의 100 seed × 12시간 기준선. 제품 구현은 후속 실행이다. 목표는 첫 영웅 환생 p50 45–60분, 90%가 90분 이내 성공, 성과 기반 새 콘텐츠 해금이 8–12시간까지 이어지는 진행이다. 진행 속도를 늦춘 것만으로 재미를 입증하지 않는다.

## 구성 작업

H07-01은 버전별 도구·작업/검증 설정·네 역할 지침·프로토콜·실행 프롬프트를 준비하고 자체검사, 정확한 저장소 게이트, 현재 앱 기준선과 앱/기존 파일 보존을 검증한다. 실제 상태는 실행 폴더의 loop.json에 기록한다. 앱 버전 0.6.0, CURRENT=v3, 기존 npm 명령과 사용자 변경을 유지한다.

## 기능 판정

동료 레벨은 게임상 상한 없이 양의 안전 정수 number로 유지한다. 레벨/별 증가의 범위를 넘으면 상태를 변경하거나 재료를 소모하지 않는다. 동료 환생 조건은 `level >= 10`으로 분리하고 Lv1/별+1을 유지하며 전후 전투력을 검증한다. 서버 업로드·응답·로컬 세이브에서 기존 Lv10 제한을 함께 제거한다. 고레벨 클라이언트 출시 전에 서버 호환을 확인한다.

영웅 도감 공개는 실제 선택 이력 또는 영구 컬렉션, 몬스터는 `speciesKills[id] > 0`을 사용한다. 후보/필드 등장만으로 공개하지 않는다. `seen*`의 추첨/해금 의미는 덮어쓰지 않는다. 기존 공개가 새 기준을 충족하지 않으면 실루엣으로 복귀하고 ACK를 제거해 나중의 첫 선택/처치가 새 알림이 되게 한다. 공개 수·미리보기·이름·설명·접근성 라벨·목표 완료도 같은 판정이다. 기록 없는 과거 처치를 현재 보유 동료나 전체 처치 수로 추정하지 않는다. PvP로만 얻은 종도 직접 첫 처치 전에는 도감 실루엣이다.

PvP는 기존 최대 50명 API와 지정 상대 선택을 재사용한다. 각 행에 순위·영웅·이름·승패·동료 파티·선택 버튼을 보여준다. 선택 강조·키보드 이동·주기 업데이트 중 포커스·오프라인·빈 목록·삭제/만료를 확인한다. 도감 실루엣 정책을 필드/환생 후보/PvP 파티 원화에 적용하지 않는다.

최소 영웅 환생 레벨은 올리되 숫자는 사전등록 비교 결과로 결정한다. 현재 `offerLevel`의 12–18 clamp와 기존 열린 후보 보존도 함께 검토한다. 후보 측정에 필요한 `eligibleHeroIds(state)`와 `eligibleMonsterIds(state)`를 실제 후보·출현 판정과 공유하여 core에서 export한다. 하네스가 성장 공식을 복제하지 않게 하는 최소 인터페이스다. 경험치/몬스터 HP/초기 포획 변경은 승인된 실험 범위다. 기존 콘텐츠 성과 조건을 먼저 조정하고 신규 강제 시간 제한·새 시스템·추가 종은 기본 범위에서 제외한다.

## 측정의 의미

기준 정책은 신규 게임, 100ms tick, 균등 2입력/초, 골드 미사용·동료 무관리, 준비 즉시 첫 후보 선택이다. 첫 준비/제안/성공 시각을 구분하고 전체 100개 중 90개가 90분 안에 성공해야 한다. 목표 중앙값 45–60분은 빠른 유저 모두를 강제로 늦추라는 조건이 아니다.

마지막 해금은 미리 이름과 hero/monster ID를 등록한 단계의 자격 충족 시각이다. 실제 첫 선택/처치까지의 지연을 별도로 기록하고 반복 스택·일반 레벨업을 새 콘텐츠로 세지 않는다. 마지막 단계 p50은 8–12시간이다. 2시간의 남은 단계, 이후 새 해금/처치/선택, 공백과 최악 정체를 보고한다.

Lv16–20 조건만 올린 대조와 최대 3개 성장 안정화 후보를 탐색 seed 10001–10020으로 120분부터 비교한다. 통과안을 12시간 비교한 뒤 검증 seed 1–100을 사용한다. 정책·수치·판정 기준은 실행 전 고정한다. 결과에 맞춰 범위를 바꾸면 새 프로토콜/근거로 재측정한다.

사람의 재미와 업무 방해는 별도 관찰 없이는 PENDING이다. 이번 기준선은 신규 설계의 성공 근거가 아니다.
