# v0.5 경험·프로필·저장 경계 검토

검토자: `/root/experience_design` · 독립 초기 검토 · 2026-09-10

검토 범위: AGENTS.md, v4 HARNESS.md, 실제 menu/hero/engine/save/identity/net/IPC 및 메뉴 테스트.
이 문서는 구현 전 제안이다. 밸런스 수치와 최종 데이터 계약은 통합 설계에서 확정한다.

## 이미 있는 것을 확장한다

- 메뉴는 420pt 창의 `hero / roster / ranking / battle` 탭이며 DOM 주입 테스트가 있다.
- 이름 변경은 `getIdentity / setName` IPC와 identity.json에 이미 있고 오프라인에서도 된다.
  프로필로 현재 `#name` 필드를 옮긴다. 두 번째 이름 저장소나 인증 토큰을 포함한 프로필을 만들지 않는다.
- `killCount`는 영웅 환생 때도 유지되는 누적 처치 수다. 별도 중복 카운터를 만들지 않는다.
- 영웅 선택은 이미 offerSerial로 오래된 클릭을 거부하고 저장된 후보를 재사용한다.
- 영웅 도감은 현재 미수집 항목까지 실제 이미지·이름을 노출하고 있어 요구와 다르다.
- 도감 50종 상한, 10–25 버프 검증, 3개 후보의 속성 중복 금지는 실제 코드 제약이다.
  레어·중첩 효과를 추가할 때 메뉴뿐 아니라 저장 파서와 서버/net 경계를 함께 검토해야 한다.

## 최소 사용자 흐름

1. **영웅**: 현재 영웅/공격력/버프/중첩, `현재 레벨 / 다음 환생 레벨`, 휴식 시간,
   후보 보기. 후보 카드에는 외형, 일반/레어, 단계, 속성, 현재 보유 수치 → 선택 후 수치,
   `첫 환생` 또는 `중첩 N → N+1`를 함께 보여준다. 낮은 단계도 유효한 선택임을 문구로 알린다.
2. **상점**: 골드 잔액, 업그레이드의 현재→다음 효과, 정확한 다음 비용, 최대 단계 표시.
   재굴림은 영웅 후보 옆에 유지해 소비 결과를 그 자리에서 볼 수 있게 한다.
3. **도감**: 몬스터/영웅을 내부 버튼으로 전환한다. `발견 X/Y`와 레어 표시를 별도로 보여준다.
   영웅 보유 외형 장착은 이곳에서 무료로 제공한다. 영웅 화면의 기존 도감은 같은 컴포넌트를
   재사용하거나 도감으로 이동하는 안내만 남긴다. 70종짜리 갤러리를 두 벌 렌더링하지 않는다.
4. **내 기록**: 이름 입력과 저장 결과, 플레이 시간, 몬스터 처치, 영웅 환생 횟수,
   영혼 회귀 횟수, 누적 PvP 승리, 최근 영웅 환생 기록. 이름 변경과 조회는 네트워크 없이 동작한다.
5. 기존 **동료/순위/대전**을 유지한다. 늘어난 탭은 좁은 창에서 줄바꿈하며 키보드 포커스가 보인다.

상점·도감·내 기록은 동일 메뉴 안의 패널이다. 별도 창이나 추가 설치는 필요 없다.
환생의 초기화 항목과 유지 항목은 후보 위에 한 번 설명한다. 별도 모달을 반복해서 띄우지 않는다.
골드가 부족하면 버튼을 비활성화하고 필요한 차액을 쓴다. 정당한 수입 없이 잔액을 낙관적으로 줄이지 않는다.

## 발견과 획득은 다른 사건이다

| 항목 | 영구 발견 시점 | 별도 획득/처치 기록 |
| --- | --- | --- |
| 영웅 | 자신의 유효한 환생 후보 3명에 실제 표시되거나 이미 보유한 영웅 | 선택 확정 시 보유·중첩·환생 기록 증가 |
| 몬스터 | 자신의 필드에 실제 생성된 시점; 저장된 현재 몬스터도 발견으로 복구 | HP가 0이 되는 중앙 경로에서 종별 처치 1 증가 |

조건 충족은 후보/출현 풀에 들어갈 자격이다. 아직 등장하지 않았다면 실루엣을 유지한다.
도감 열기, 구매, 재로드, 남의 PvP 영웅/동료 보기만으로 새 종을 발견 처리하지 않는다.
환생·영혼 회귀·영웅 장착 변경은 발견 사실이나 누적 달성 조건을 지우지 않는다.

미발견 카드도 펼칠 수 있고 **발견 조건과 현재 진행도는 무료로 확인**할 수 있다.
이 요구에서 '비밀'은 조건을 만족한 후 등장하는 숨은 콘텐츠로 해석한다. 아무 단서 없이 시행착오만
강요하는 것으로 해석하지 않는다. 설명·능력치는 발견 뒤 공개하고, 미발견에는 조건 단서와 `미발견`을 쓴다.
이미지의 불투명도를 낮추는 것은 실루엣이 아니다. 실제 스프라이트의 불투명 픽셀을 한 색으로 그려
무늬/팔레트가 드러나지 않게 한다. 읽기 보조 텍스트도 `미발견 레어 영웅`처럼 노출 수준과 일치시킨다.

자기 자신 처치/환생만으로 처음 열리는 조건, 서로만 요구하는 두 레어 종, 이전 버전에서
저장하지 않은 기록만으로 영원히 잠기는 조건을 금지한다. PvP 전용 해금은 일부로 제한하고
오프라인에서 가능한 레어 경로를 충분히 둔다. 시간 조건은 정확한 시간대/기준을 도감에 쓴다.

## 기록과 마이그레이션

- 플레이 시간은 엔진의 주입된 tick으로 누적하는 앱 실행 시간이다. 메뉴를 열거나 게임을 숨겨도
  엔진이 진행하면 포함하고, 앱 종료 시간과 절전으로 발생한 거대한 dt는 포함하지 않는다.
  유효 숫자/음수 검증을 하고 종료·재시작 후 누적이 이어지게 저장한다.
- 종별 처치는 중앙 `applyDamage`의 실제 사망 처리에서만 증가한다. 스플래시/동료 공격/보스
  처리마다 따로 올리지 않는다. 새 종 및 재생·복제된 이벤트로 이중 증가하지 않는 테스트가 필요하다.
- 영웅 환생 기록에는 순번, 선택 영웅 ID, 선택 당시 레벨, 적용 후 중첩/버프, 당시 누적 플레이 시간을
  저장한다. 실제 시간은 주입하지 않는 한 만들지 않는다. `장착`은 환생 이력이 아니다.
- 전체 통계/영웅별 환생 횟수는 유지하고, 타임라인은 최근 100개로 제한한다. 메뉴는
  `총 N회 · 최근 100개`를 명시한다. '이 영웅으로 환생한 적 있음' 조건을 잘린 배열로 검사하지 않는다.
- 기존 저장에는 예전 플레이 시간·정확한 종별 처치·영웅별 반복 횟수가 없다. killCount와
  hero.reincarnations는 유지한다. 예전 데이터를 추측해서 분배하지 않는다. 기존 collection은 최소
  1회 보유 사실로 옮길 수 있으나 이전 환생의 정확한 시간/순서는 `이전 버전 기록 없음`으로 표시한다.
- 신규 레코드는 알려진 카탈로그 ID만, 유한한 비음수 정수만 받아들인다. 배열/맵 크기를 제한한다.
  깊은 복사가 빠져 `getState / toSave`의 결과를 수정해 엔진 상태가 변하지 않아야 한다.
- 도감 발견 플래그는 전투 생성/제안 생성과 같은 저장 스냅샷에 들어간다. 실패한 선택/부족한 골드/
  오래된 serial은 골드, 중첩, 기록, 발견을 변경하지 않는다.

## 경계 위험과 구현 시 수정할 곳

**PvP 중복**: 현재 `pvpResult`는 `won/stolen/lostId/replay`만 받고 match ID가 없다.
신규 PvP 해금 카운터를 이 액션의 호출 횟수로 만들면 재전송에 취약하다. 성공 응답의 match ID와
봇 여부를 main에서 붙이고, 처리한 match ID를 영구 저장해 같은 결과를 한 번만 적용해야 한다.
가능하면 main의 성공 응답 경로가 공식 결과를 전달하고 메뉴에서는 같은 결과를 재전달하지 않는다.
훈련 허수아비 승리는 PvP 조건을 올리지 않는다. 인증 실패/네트워크 실패도 기록하지 않는다.

**이름**: 현재 서버와 클라이언트 모두 `^[A-Za-z0-9_-]{1,16}$`다. 이 범위를 유지하면 입력 옆에
`영문·숫자·_·- 1–16자`를 알려야 한다. 한글 이름을 지원하기로 결정하면 동일 shared 규칙과
서버 검증을 함께 바꾸고 정규화/길이 기준을 테스트한다. 과거 인증 토큰이나 playerId를 초기화하지 않는다.
기존 setName은 거부된 이름에 이전 값을 돌려주므로, 화면은 조용히 원복하기보다 실패 설명을 보여준다.
초기 identity 응답이 늦게 도착해 입력 중인 이름을 덮어쓰지 않게 한다.

**효과와 서버**: 버프 상한·새 ID를 늘리면 서버 snapshot parser, 상대 디렉터리 응답 parser,
PvP power/replay가 모두 같은 유효 범위를 받아야 한다. 미배포 서버가 새 영웅을 거부하는 경우
오프라인 게임·이름·도감·기록은 정상 동작하며 배포 확인과 기능 검증을 구분해 기록한다.

**메뉴 갱신**: autosave마다 도감 100개를 새로 만들지 않는다. 현재 영웅 controls/gallery처럼
발견/보유/중첩/장착 상태가 바뀔 때만 다시 만들고 펼친 항목·스크롤·입력 포커스를 유지한다.
재굴림·구매 버튼은 offerSerial 또는 예상 업그레이드 단계를 보내 큐에 남은 더블클릭을 방지한다.

## 검증 제안

1. 초기 저장: 모든 미발견 카드는 단색 실루엣, 조건 확인 가능, 실제 이름/버프는 등장 뒤 공개.
2. 영웅 후보 열기→보류→재시작: 후보 등장 발견은 유지되고 보유/중첩/환생 횟수는 늘지 않음.
3. 같은 영웅을 약한 roll로 반복 선택: 화면 예고와 실제 적용 수치가 일치하며 이전보다 개선.
4. 골드 구매/재굴림의 부족·오래된 요청·재로드·중복 클릭: 정확히 한 번 소비하거나 무변경.
5. 환생/회귀/장착 변경 후 누적 시간·처치·발견·기록 유지, 단계별 다음 레벨 문구 일치.
6. 같은 공식 PvP 결과 두 번·봇·실패: 해당하는 실제 상대 승리 한 번만 카운트.
7. v1/v2/v3 저장 마이그레이션: 기존 자산 보존, 알려지지 않은 과거 시간/종별 수치 생성 없음.
8. 도감 펼침/이름 편집 중 autosave: 펼침과 미저장 입력 보존; 420pt/좁은 창에서 가로 넘침 없음.

자동 DOM/엔진 검증과 실제 사람의 발견 재미 평가는 다른 증거다. native smoke/package 및
실서버 호환성은 통합 담당자의 별도 릴리스 기록에 남긴다.
