## 현황과 반드시 보존할 계약

- 영웅 h01–h50은 ID별 단계/속성/버프가 이미 저장과 PvP에서 공유된다. h00 기본 영웅도 유지한다.
- 몬스터는 105종이다. `SPECIES_IDS` 순서뿐 아니라 길이도 저장에 종이 없을 때의 복원 및
  tier 계산에 쓰인다. 레어를 추가하면서 길이가 135가 되면 기존 세이브의 종과 색 단계가
  바뀐다. 기존 105개를 `COMMON_SPECIES_IDS`로 분리하여 복원/일반 추첨/tier의 주기로 유지한다.
  `SPECIES_IDS`는 105개 뒤에 레어 30개를 붙인 전체 유효 ID 목록으로 사용한다.
- 영웅 수집 파서 cap 50, 그림 레지스트리 길이 50, 메뉴 문구 `/50`를 70으로 확장해야 한다.
- 현재 도감은 미획득 영웅도 모든 그림을 보여준다. 미발견은 실제 canvas tint로 가린다.
- 몬스터 공격 시간/타입/사이즈는 모든 ID의 Record다. 30종마다 이 세 표와 그림이 필요하다.
  보스 여부는 종의 레어도와 독립적으로 8번째마다 그대로 적용한다.
- `pvpResult`는 렌더러에서 보내므로 그것만으로 영구 PvP 업적을 더하면 중복/위조 입력으로
  조건을 열린다. 메인에서 확인한 서버 결과를 unique match ID와 함께 한 번만 반영한다.
- 기존 `rebirths`에는 동료 시스템 환생도 섞인다. 영웅 환생 기록은 `hero.reincarnations` 기준이다.

## 최소한의 데이터와 함수

새 `src/core/discovery.ts` 하나에 콘텐츠 설명과 조건을 두는 제안이다. 범용 퀘스트 엔진은 만들지 않는다.
`RareHeroDef`는 id/name/description/type/buff/rank/requirements, `RareMonsterDef`는
id/name/description/type/size/attackDelayMs/requirements. 영웅은 rarity와 조건만 추가하고
기존 버프 함수를 재사용한다. 레어 등급과 시각 단계 rank는 별개다. 레어 영웅의 기본 수치 예산도
일반과 같으며, 같은 영웅 중첩 강화는 모든 외형에 공통 적용해 취향 선택을 살린다. 레어의 rank는 그림 단계이며
레어 제안 자격은 비밀 조건만 판정한다. 일반 영웅의 rank 해금 제한을 레어에 중복 적용하지 않는다.

조건은 작은 discriminated union으로 충분하다:

- `speciesKills(id, count)`, `elementKills(type, count)`, `totalKills(count)`
- `heroHistory(formId, count)` 또는 `heroFamilyHistory(jobIndex, count)`
- `equippedType(type)`, `heroReincarnations(count)`
- `playTimeMs(ms)`, `phase(새벽|낮|황혼|밤)`
- `pvpWins(count)`, `discoveredMonsters(count)`, `goldSpent(count)`
- 한 항목의 배열은 AND, 오프라인 대체 조건이 필요하면 OR 배열 하나로 명시한다.

부가 저장 값은 `progress`에 둔다: `playTimeMs`, `speciesKills`, `seenMonsters`, `seenHeroes`,
`pvpWins`, `confirmedMatchIds`(최근 100개), `goldSpent`, `rareMisses`.
영웅 환생 순서/횟수는 hero 모듈 소유 기록을 조회한다. 타입 처치 수는 135개 종별 수에서
필요할 때 합산한다. 화면 새로고침마다 거대한 이벤트 로그를 재생하지 않는다.
`conditionStatus(requirement, context)`는 완료 여부와 표시용 현재/목표를 함께 반환한다.
임의 ID, NaN, 음수, 소수, unsafe integer, prototype key는 저장 경계에서 폐기/제한한다.

## 발견과 해금의 구분

- **조건 달성**은 추첨 풀에 들어갈 자격이다. 달성만으로 그림이나 이름은 공개하지 않는다.
- **발견**은 영웅이 세 선택지에 실제 나타난 순간, 몬스터가 필드에 생성된 순간이다.
- **소유**는 영웅 환생 수락 또는 동료 포획이다. 발견한 영웅이어도 미소유면 장착할 수 없다.
- 기존 저장은 수집 영웅+열린 선택지를 발견으로, 현재 몬스터+보유 동료를 발견으로 이관한다.
  과거의 종별 처치/플레이 시간/환생 순서는 알 수 없으므로 지어내지 않는다. 총 처치 수와 환생 수는
  기존 실제 수치를 유지한다. 히스토리에 `종별·순서 기록은 v0.5부터`를 짧게 표시한다.
- 미발견 도감: 단색 실루엣, `???`, 레어 등급/속성, 간단한 단서와 조건 진행을 표시한다.
  설명/정확한 이름/보유 버프는 발견 후 공개. 상세 조건은 접기/펼치기로 볼 수 있다.
  정확한 조건과 진행 수치는 항상 무료로 펼쳐 볼 수 있다. 골드 연구로 정보를 잠그지 않는다.

## 시간·확률·오프라인 설계

시간대 조건은 현실 심야 강요를 피하고 저장되는 활성 플레이 시간의 **필드 시간**을 쓴다.
20분 한 주기: 새벽 0–5분, 낮 5–10분, 황혼 10–15분, 밤 15–20분. 메뉴에 현재 시간대와
다음 전환까지 남은 플레이 시간을 표기한다. 코어는 Date를 읽지 않고 `tick` 주입값만 쓴다.
실제 시각이 꼭 필요한 확장이 생기면 별도의 주입 컨텍스트로 도입하며 이 릴리스에 섞지 않는다.

레어 몬스터는 일반 몬스터와 같은 HP/보스 배율을 따른다. 레어 자체가 벽이 되거나 무료 골드가
기하급수로 불어나지 않는다. 평상시: 조건을 모두 만족하는 레어가 있을 때 12% 레어 추첨,
11번 연속 자격 있는 일반 생성이면 12번째에 레어 보장. 레어가 없는 동안은 보장 카운터를
소모하지 않는다. 레어 선택은 아직 못 본 후보 우선, 전부 발견했다면 모두에서 균등이다.
조건은 **새 몬스터 생성 시점**에만 확인한다. 이미 나온 몬스터를 시간 변화로 없애지 않는다.
보스 주기, 포획 규칙, 랜덤 주입을 유지한다. 기존 첫 몬스터와 일반 추첨은 공통 105종 사용.
골드 유인 향은 레어 가능 생성 20회 동안 레어 확률을 25%로 높인다. 비용은
`75+25×min(영웅 환생 수,100)`이며 가능 레어가 없으면 차감하지 않고 기간도 소모하지 않는다.

영웅 레어 20종은 조건 달성 후 일반 세 선택지의 후보가 될 수 있다. 첫 슬롯은 최고 단계 일반 영웅, 두 번째는 재등장/하위 단계, 세 번째는 레어 기회로 한다.
중복 중첩 수치와 세 슬롯의 타입 충돌 해결은 hero 담당의 최종 규칙으로 하나로 합친다.
세 번째 슬롯은 앞선 두 슬롯과 다른 속성의 미발견 레어가 있으면 반드시 제안한다.
호환되는 미발견 레어가 없을 때만 가능한 발견 레어 풀을 25% 확률로 제안한다. 자동 무료 보류도 기회로 세며 재굴림 금액으로만 접근할 수 없어야 한다.
영웅/몬스터 상태별 eligible 풀 계산은 seed 고정으로 완전히 재현 가능해야 한다.

## 연결 지점과 검증

- `core/monsters.ts`: 공통 105개 순서 고정, 30개 정의와 table 추가, legacy tier 상수 105.
- `core/discovery.ts` (신규): 조건 정의/evaluator/설명/컨텍스트/진행 파서와 짧은 헬퍼.
- `core/hero.ts`: 레어 정의 병합, 자격 풀 필터, 선택지 생성 순간 발견 기록. hero 담당과 파일 소유 분리.
- `core/engine.ts`: spawn 선택기/발견, applyDamage 종별 처치, tick 활성 시간, 저장 복사.
- `core/save.ts`, `types.ts`, `index.ts`: 부가 progress 저장과 파서; 무효 필드가 원래 세이브를 지우지 않음.
- `menu/hero.ts`, 새 도감 패널: 미발견 실루엣, 발견/소유 구분, 설명/실제 스탯/조건 진행.
- `renderer/sprites/heroForms.ts`, 새 `heroRareLooks.ts`, `species/rare.ts`, `monsters.ts`: 50종 코드 그림.
- `main/net` PvP 성공 경로: 실제 응답의 match ID 1회 반영. 통신 불가 시 오프라인 대체 조건 작동.

필수 결정적 테스트: 20/30개 정확한 수와 ID 유일성; 조건 각각의 직전/정확 경계;
모든 조건에 만족 컨텍스트가 존재(순환 불가); 어떤 잠긴 레어도 나오지 않음;
free RNG와 12회 보장; 주입 시간대 경계; 조건이 사라져도 현재 몬스터 유지;
발견/소유 구분; 저장/복사 별칭 방지; 오염 값/중복 입력/재시작;
이전 105종 복원/단계 불변; 모든 70개 영웅과 135개 몬스터 그림 완전성;
미발견 canvas 단색과 발견 후 실제 팔레트.

전체 수용 검증은 `npm test && npm run lint && npm run typecheck`이며 실제 앱 외형/입력 흐름은
권한 있는 통합 담당자가 확인한다. 이 문서는 설계 제안이며 구현/실측 통과를 주장하지 않는다.

## 병렬 구현용 API 합의 제안

`discovery.ts`는 MonsterType만 type-import한다. hero/monsters 런타임 모듈을 import하지 않아
양쪽이 카탈로그를 안전하게 import한다. exports: `RARE_HERO_FORMS`, `RARE_MONSTERS`,
`Requirement`, `DiscoveryContext`, `conditionStatus(requirement, context)`, `requirementsMet`.
컨텍스트는 작은 값 객체: `killCount`, `playTimeMs`, `speciesKills`, `elementKills`,
`heroCounts`(영웅 ID별 횟수), `heroFamilyHistory`(10개 직업별 횟수), `reincarnations`, `uniqueHeroes`, `equippedType?`,
`seenMonsters`(string[]), `pvpWins`, `goldSpent`. 타입별 처치/계열 횟수는 상태 소유자가
현재 카탈로그와 hero별 누적 환생 횟수로 산출한다. 최근 히스토리 목록의 보관 상한으로
영구 해금이 취소되면 안 되므로 per-form aggregate를 기준으로 한다.
