게임 하네스
너는 AI 에이전트 워크플로우 엔지니어다.

.agentdoc/{datetime}/ 은 프롬프트 관측을 위해 로그를 저장한다. 에이전트에 입력한 프롬프트 원본이 저장된다. 그리고 세션 기록이 저장되고 plan모드에서 생성 또는 수정된 plan을 저장한다. 세션이 종료되면 해당 세션의 handoff를 위한 요약이 저장된다. 

.harness/{version}/ 에 업데이트된 하네스 구현을 먼저 해주고 완료되면 그 위에 에이전트들을 동작해서 개발을 진행한다.

하네스 구성은 프롬프트 또는 스킬 ‘one shot’으로 구현과 검증까지 완료 해야한다.
스킬은 plan -> dev -> eval 3단계를 거치도록 적당한 prefix를 부여한다

아래 아이디어를 바탕으로, 단순한 앱을 바로 구현하는 것이 아니라 AI가 스스로 기획, 작업 분해, 구현, 검증, 수정, 완료 기록까지 수행할 수 있는 원샷 하네스를 구성하고 개발을 완성해라.

**하네스에 필요한 에이전트**

1. Spec Clarifier
   모호성 제거 담당

2. Planner
   PRD와 작업 단위 분해 담당

3. Builder
   멀티 에이전트 조율과 작업이 완료될 때까지 에러가 발생해도 멈추지 않고 해결책을 찾아 다시 시도

4. Validator / Packer
   검증, 패키징, 핸드오프 담당


**루프엔지니어링**

1. 스펙 (수렴 조건의 정의)
가장 중요. 루프가 “언제 끝났는지” 판단할 테스트 가능한 합격 기준이 없으면 영원히 안 끝나기 때문에 테스트 가능한 합격 기준이 있는 명확한 스펙이 루프가 작업이 진짜 완료됐는지 알기 위한 필수 조건이 필요하다. SPEC.md 또는 PRD.md에 기능별로 “통과 = 무엇”을 정의한다.

2. 계획 파일 (디스크 위의 기억)
IMPLEMENTATION_PLAN.md. 첫 이터레이션에서 plan 모드로 스펙과 코드를 비교해 우선순위 task 목록을 만든디. 각 이터레이션은 계획에서 task를 하나만 골라 구현·테스트·커밋한 뒤 fresh context를 위해 종료하고, 루프가 갱신된 계획을 다시 읽어 다음 task를 선택한다.  이게 컨텍스트가 차서 망가지는 걸 막는 핵심 구현 방법이다.

3. AGENTS.md / CLAUDE.md (루프의 심장)
AGENTS.md가 루프의 심장이며, Ralph가 프로젝트를 어떻게 컴파일하고 실행하는지를 지시 합니다. 빌드 명령, 테스트 명령, 실행 방법, “끝났다고 선언하기 전 반드시 통과해야 할 것”을 여기 적는다.

4. 검증 게이트 (종료 조건)
랄프 루프는 한 이터레이션당 task 하나를 격리하고, 검증을 종료 게이트로 사용한다. 즉 test && lint && typecheck가 초록불이 아니면 루프는 못 빠져 나오도록 하여 이게 “처음엔 잘하다 망가지는” 현상을 구조적으로 차단한다.

5. 루프 러너 (fresh context)
두 가지 모드가 있는데, shared context는 세션을 유지해 자기검토를 하고, fresh context는 매 이터레이션 새 세션을 시작해 확증 편향을 제거하며 모델은 레포와 스킬 파일만 본다.  원샷 신뢰성을 원하면 fresh context가 정석이다. 같은 세션을 강제로 이어가는 exit-hook 방식은 컨텍스트 오버플로우와 손실 압축을 유발하지만, 매 task마다 깨끗하게 종료 후 재시작하는 방식은 그렇지 않기 때문이다.

6. 완료 센티넬 (루프 탈출 신호)
모든 기준이 충족되면 모델이 <promise>DONE</promise>를 출력하게 하고, 루프는 그 promise가 나오거나 max-iterations에 도달할 때까지 계속 된다. 무한 루프 방지 상한선은 필수다.


**개발목표:**

게임제목: Desktop Monster (DesMon) 게임방법: Steam 의 BongoCat(https://store.steampowered.com/app/3419430/Bongo_Cat/?l=koreana)을 레퍼런스로 맥과 윈도우의 데스크탑에서 실행되고 작게 보여지는 게임이다. 게임 방식은 BongoCat을 카피하지만 캐릭터와 연출부분은 다르다

캐릭터&연출: 기본적으로 도트디자인이다. 픽셀 그래픽으로 간단하게 보여질 수 있도록 해야한다. BongoCat 정도 작은 크기의 필드가 있고 왼쪽 또는 오른쪽에 Hero가 있고 그 반대쪽에는 Monster가 있다. BongoCat 처럼 유저가 키보드를 치거나 마우스로 클릭되는 모든 행동이 포인트로 입력되듯이 해당 클릭을 할때마다 몬스터를 공격한다. 몬스터는 공격을 맞고 있다가 체력 게이미지바에서 게이지를 표시하고 체력을 모두 소모하면 몬스터가 퇴장하게 되고 다음 몬스터가 신규등장한다. 몬스터가 처치되면 몬스터에게서 아이템이 튀어나오고 자동으로 수집하게 된다. 영웅은 몬스터를 처치할때마다 경험치를 얻고 레벨이 올라가게 된다. 영웅의 모습은 도트로된 칼을 가진 기사의 형태이다.
