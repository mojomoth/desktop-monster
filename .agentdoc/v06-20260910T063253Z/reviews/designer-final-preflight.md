# Designer 최종 사전 점검

검토자: 이번 실행의 실제 Designer 에이전트 `/root/designer`.
이 문서는 최종 4역 감사 응답이나 출시 승인 문서가 아니다. 읽기 전용 검토를 수행했고
이 문서 외의 파일을 수정하거나 Electron을 실행하지 않았다.

검토 시작 당시 소스는 `c1b3603ed446d75fdd4830e59aac930d5fad73d17c6bef7de6c888b062914aef`,
평가 도구는 `d402273c4cae0e9d597a4efe3a5648ac56cc2ad4c121e5c483b71f7710797de8`이었다.
아래 Native 진단 공백을 호스트가 수용했으므로 평가 도구와 최종 실행 근거는 이후 다시 고정해야 한다.

## 판단

현재 읽은 구현에서 새 blocker/major 기능 오류는 찾지 못했다. 앞서 보고한 저장 오류의 화면 밖 표시와
환생 상한의 불가능한 새 후보 안내는 수정되어 있다. 다만 필수 Native journey의 두 상태 전이는
기존 검사 이름만으로 완료 처리할 수 없어 보완을 요청했다. 사람의 이해도·재확인 동기·업무 방해는 PENDING이다.

### 검증 보완 요청

1. **major · Native의 실제 추가 발견과 이전 확인 요청 순서가 빠짐.**
   검토 당시 `v06-journey.cjs`는 처음부터 `seenHeroes=[h01,h02,h03,h04]`인 fixture를 열고,
   표시한 첫 세 명을 확인한 뒤 같은 확인 요청을 재전송했다. `h04`가 남는다는 결과는
   이미 발견됐지만 화면에 표시되지 않은 ID 보존의 근거다. 표시 이후 새 발견이 발생하는 순서를
   실제로 실행한 근거는 아니다. 반면 `tests/progressV6.test.ts`는 이전 표시 집합을 만든 뒤
   `heroOffer`로 새 발견을 만들고 이전 요청을 적용하는 코어 회귀를 갖고 있다.
   호스트에 Native에서도 표시 집합 고정 → 실제 `heroOffer` IPC → 새 seen ID 확인 →
   이전 snapshot 확인 요청 → 새 ID가 모두 미확인으로 남음의 순서를 요청했다.
   호스트는 진행 중 matrix와 실험을 보존·중단하고 이 진단을 보완한 뒤 새 지문으로 재실행하기로 했다.

2. **major · 동일한 목표의 미발견→발견 완료 전이가 Native에서 빠짐.**
   검토 당시 `v06-goal-discovered-unowned`는 미발견 `h51` 목표에서 이미 발견한 `h02`로
   목표를 바꿔 완료 문구를 확인했다. 발견/보유 구분은 확인하지만 선택한 목표 자체의 완료 전이는
   실행하지 않는다. 같은 goal ID가 유지된 채 실제 새 발견 또는 명시적으로 구분한 전후 fixture로
   발견 완료가 표시되고, 목표가 자동 변경·해제되지 않는 진단이 필요하다.
   코어와 메뉴 단위 검사에는 같은 목표의 발견 상태 전이가 있으므로 구현 오류로 단정하지 않는다.

## 현재 구현에서 확인한 계약

| 영역 | 확인과 근거 |
| --- | --- |
| 발견 요약 | `mountCodex`는 영웅/몬스터별 미확인 수를 표시하고 각 세 개 카드만 미리 보여준다. 확인 이벤트는 그때 표시한 ID 배열 복사본만 보낸다. 화면을 여는 동작 자체는 확인하지 않는다. `quick-03.json` checks 22–24와 메뉴/코어 회귀가 이를 뒷받침한다. 실제 추가 발견 순서에 대한 한계는 위에 별도로 적었다. |
| 미발견 정보 보호 | 목표는 번호·종류와 `미발견`으로 표시한다. 영웅 카드의 이름·설명·능력치는 실제 seen 전까지 가려지고 아트는 단색 실루엣이다. 적격과 발견 완료, 영웅 발견과 보유를 다른 문구로 표시한다. `v06-goal-focus.png`를 직접 열어 확인했다. |
| 목표 선택과 유지 | 무료 선택/변경/해제는 기존 도감 안에 있고 별도 보상 수령이나 만료가 없다. 조건은 기존 `conditionStatus`로 다시 계산하며 phase/equippedType 같은 조건이 다시 미달이어도 저장된 goal을 바꾸지 않는다. `tests/progressV6.test.ts`, `tests/menu.test.ts`의 관련 회귀를 읽었다. |
| 갱신 중 조작 보존 | 도감 카드·summary·목표 버튼을 최초 생성 후 재사용한다. `quick-03.json` check 26은 실제 5.2초 경과 후 focus 유지, 열린 details 유지, scrollY 5953→5953을 기록한다. |
| 저장 실패 | `#save-status`는 패널 위에 있고 sticky·`role=status`·`aria-live=polite`를 사용한다. `v06-save-failed.png`에서 화면 위의 오류를 직접 확인했다. check 29는 실제 쓰기 실패, 화면 내 가시성, 저장된 목표 null과 UI의 목표 없음 유지를 함께 확인한다. check 30은 복구 후 저장 및 오류 해제를 확인한다. 실제 VoiceOver 낭독은 실행하지 않았으며 DOM 접근성 계약과 시각적 가시성의 근거로 한정한다. |

## 근거의 범위와 남은 관찰

- `quick-03.json`은 source `9338cd2015a9c4a8d47f7438cc7cb9b744a9726d9abffb4ed1cc002019ef8a08`의
  0분 개발 진단 35개 통과 기록이다. 최종 source와 다르므로 최종 동일 소스 Native 9개를 대체하지 않는다.
- quick-03에 기록된 스크린샷 15개 모두 파일 SHA-256을 재계산해 원본의 해시와 일치함을 확인했다.
  이 중 `codex.png`, `v06-goal-focus.png`, `v06-save-failed.png`, `v06-discoveries.png`,
  `v06-training.png`, `level-gate.png`를 직접 열었다.
- **시각 근거 공백:** `v06-discoveries.png`는 scrollY 약5953의 목표 카드를 보여주고,
  `codex.png`의 요약은 미확인 0개 상태다. 실제 발견 카드가 채워진 요약을 보여주는 스크린샷이
  없어 그 상태의 전체 배치까지 관찰했다고 주장할 수 없다. populated 요약의 스크린샷을
  추가하는 것이 좋으며 현재 코드의 clipping/오버플로 오류를 발견했다는 뜻은 아니다.
- 빈 요약과 목표 없음 안내가 첫 화면에서 상당한 높이를 쓴다. `codex.png`의 도감 카드는
  첫 viewport 아래에서 시작한다. 목표 선택을 자발적으로 찾는지, 읽음 처리를 의무로 느끼는지는
  사람 관찰에서 확인할 문제다. 그 관찰 없이 화면을 더 줄이거나 안내를 강화해야 한다고 단정하지 않는다.
- journey의 `v06-restart-ui-state`는 renderer 재로딩이다. 실제 앱 프로세스 종료/재시작은
  최종 0.6 패키지의 `package-check.mjs`로 별도 확인해야 한다. 임시 개발 패키지 결과는 최종 결과가 아니다.
- 새 강제 창·소리·수령 기한은 추가하지 않았다. 실제 업무 방해, 접근성 권한·전역 훅, 운영 PvP,
  사람 재미 검증은 이 사전 점검에서 실행하지 않았다.

관련 로그: `evidence/final-ac-03.log`에는 최종 소스의 관련 8개 파일·157개 검사 통과가 기록돼 있다.
이 사전 점검은 그 로그와 소스를 읽었으며 게이트를 중복 실행하지 않았다. 최종 판정은 보완한
Native journey와 새 지문에 연결된 9개 관측, 4역 공식 감사, 패키지 검증을 받은 뒤 호스트가 기록한다.
