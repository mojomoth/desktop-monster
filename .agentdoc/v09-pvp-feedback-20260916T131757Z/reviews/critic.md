# Critic — PvP 버튼 피드백

## 코드 검토

보존본 대비 `src/menu/index.ts`, `static/menu.css`, `tests/menuV9.test.ts`를 읽었다. **현재 diff의 요청·상태·보상 처리에서 P0/P1을 발견하지 못했다.** 제품·테스트·저널을 수정하거나 검증을 중복 실행하지 않았다.

- 완료 시 초기화되는 `selectedOpponentId`와 별도로 피드백 상대 ID/문구를 보관하므로 빠른 실패와 성공 결과가 카드에 남는다. 동일 ID의 DOM 노드를 유지하고 메시지가 바뀔 때만 textContent를 갱신해 자동 저장·목록 재정렬에도 보존된다.
- 진행·다른 전투 진행·목록 갱신·cooldown을 버튼 및 접근성 이름에 표시한다. 기존 중복 클릭·다른 상대·파티 잠금 가드를 유지하며 API 호출이나 main 소유 보상 적용을 추가하지 않았다.
- 기존 오류 매핑을 재사용하고 Promise 거절은 network 문구로 표시한다. 테스트는 6개 실패 종류, 재시도, 성공 결과의 올바른 상대 카드, 자동 저장·재정렬 보존, 중복 요청 방지 및 main 소유 보상을 확인한다.
- 실제 `edge-bottom/pvp-feedback.json`에서 버튼이 화면 하단에 있을 때 인라인 상태도 보이지 않는 반례를 읽었다. 메시지가 바뀌고 해당 버튼에 포커스가 남은 경우에만 `scrollIntoView({block:'nearest'})`를 실행하는 후속 수정은 그 원인에 맞다. 자동 저장에는 반복 스크롤하지 않으며 포커스를 다른 탭으로 옮기면 응답 도착 시 스크롤하지 않는 검사가 추가됐다.
- 마지막 CSS의 `scroll-margin-block: 8px`은 화면 경계에서 상태가 소수 픽셀로 잘리는 실제 반례에 여유를 준다. 가시성 검사 기준을 낮추는 변경이 아니다.

비차단 한계: 사용자가 휠로 스크롤만 하고 버튼 포커스는 유지하면 완료 응답 때 상태가 한 번 다시 보이도록 이동할 수 있다. 현재 요청 범위에서 추가 수정이 필요한 결함으로 판단하지 않는다. 이 피드백 수정은 운영 서버의 가용성·업그레이드 또는 모든 네트워크 실패의 해결을 의미하지 않는다.

## 최종 증거

8px margin 적용 후 실제 하단 버튼 실행 결과와 최신 게이트·Designer 최종 판단 확인을 기다린다. 앞선 가시성 실패는 보존된 반례이며 최종 PASS로 재분류하지 않는다.
