### 3.2 만석(A3')의 순간 — 실제로 보이는가

- active 30분: 40/40 seed가 만석에 도달(p50 **1,167초 = 19.5분**, 최소 679초, 최대 1,416초).
  그 뒤 `companionReleased` 이벤트가 p50 **21회**(min 13, max 40) 발생하고 그중 **p50 10회가 영혼 +1**을 동반한다.
- 이벤트는 무음이 아니다: `src/renderer/game.ts:777-789`가 몬스터 자리에 플로팅 텍스트
  `RELEASED +1`(영혼 있을 때) 또는 `RELEASED`를 띄우고, **로스터 최약체보다 강한 보스였으면 주황(`COLORS.orange`), 아니면 회색(`COLORS.steel`)**으로 색을 바꾼다.
- 그 "주황" 비율이 실측 **90.9%(active 30분) / 88.4%(intermittent 30분)** 다 —
  즉 만석 이후 방생의 대부분은 "지금 데리고 있는 최약체보다 좋은 놈을 놓쳤다"고 색으로 말한다.
  이건 정보이자 잔소리다. 30분에 21번 뜨는 주황 토스트가 유쾌한지 성가신지는 **사람만 판단할 수 있다(PENDING)**.
- 그 순간 취할 수 있는 행동: 필드에서는 없음(표시 전용). 트레이 → 메뉴를 **플레이어가 직접 열면**
  `src/menu/index.ts:352-368`이 `동료 30/30 · … 놓아준 보스 N마리가 영혼 M을 남겼습니다`를 쓰고
  바로 아래 **`가장 약한 <이름> 방출` 버튼 한 개**를 준다(눌러도 자동 선택은 없고 `sacrifice` 1건).
  Consume / Fuse / Sacrifice 경로도 그대로 있다.
- **보상이 사라지는 시나리오는 0건**이었다: 만석 draw는 전부 이벤트 + `releasedCount` 증가로 관측됐고
  2회당 영혼 1(`RELEASES_PER_SOUL`)이 실제로 `state.souls`에 들어갔다(P1의 `releasedWithSoul` = `floor(released/2)`).
- idle 30분에서는 만석이 1/40 seed에서만 일어난다 → **A3'의 효과는 idle에서 사실상 0**이다(밸런스의 같은 결론과 일치).

### 3.4 도감(A5')과 "다음에 볼 것"

- 9/9 시나리오에서 `unseenFirstCardRatio = 1.0`. 오퍼가 열릴 때 첫 카드는 **항상 미수집**이었다.
- 도감은 환생 수를 정확히 따라간다: 5분 2/50 → 15분 7/50 → 30분 15/50 (active/intermittent).
  before의 14종 정체는 재현되지 않았다. 30분이 끝나도 **35종이 남아 있다** — "다음에 볼 것"은 항상 남는다.
- 메뉴 헤딩이 그 숫자를 말한다: 오퍼가 열려 있으면 `다음 생의 영웅을 고르세요 · 도감 N/50`,
  갤러리 `summary`는 `영웅 도감 · N/50 (보유 외형은 무료 교체)`(`src/menu/hero.ts:53,84`).
- 카드마다 `NEW · 미수집 영웅` / `보유 · 기존 … (높은 수치 유지)`가 붙어 중복 선택이 손해가 아님을 말한다.

### 3.6 desktop interruption budget (선택 기회 / 포커스)

- 선택 기회(오퍼)는 **30분에 정확히 15회**(active/intermittent, 100 seed 전부 min=p50=max=15), 즉 평균 **120초에 1회**.
  5분 2회, 15분 7회. `HERO_REST_MS=120000`이 상한을 구조적으로 고정한다.
- 그 15회는 **모달이 아니다.** 필드에는 `REBIRTH READY` 텍스트만 뜨고, 선택창은 메뉴 창 안에 있다.
- 메뉴 창을 여는 경로는 `showMenuWindow()` 하나뿐이고 유일한 호출자는 `src/main/index.ts:166`의 **트레이 메뉴 항목**이다.
  `app.focus({ steal: true })`는 `menuWindow.ts:21,51`에만 있고 둘 다 그 사용자 클릭의 하위 경로다.
  `heroReady`/`companionReleased` 이벤트는 `src/main/`에 도달하지 않는다 → **게임이 스스로 포커스를 뺏는 경로 0.**
- 자동 알림은 하나 있다: PvP 동료 도난 시 `new Notification(...).show()`(`src/main/index.ts:82-89`).
  서버 이벤트라 이번 9시나리오(오프라인)에서는 0회 발생했고, 온라인에서의 빈도는 **미확인(PENDING)**이다.
- 강제 시간 제한/일일 로그인 요구/타임아웃 실패 경로는 코드에 없다. 오퍼는 열릴 때까지 기다리고 사라지지 않는다.

### 3.7 자연 시작 vs 복귀 세이브 vs 순수 방치 (대조군, `playtest-raw.json.controls`)

| 대조군 | 30분 결과 |
|---|---|
| **순수 방치**(동료 0, 온보딩 없음, 입력 0) | 처치 **0**, Lv1, 오퍼 0, 도감 0, 게이지 0%, 무표시 100% — **완전 정지** |
| **복귀 세이브**(동료 12, 환생 5, 도감 5, 입력 0) | 처치 1,068, 오퍼 15, 도감 5→**20/50**, 동료 30/30 만석, 방생 8회, 게이지 **99.2%**, 최장 무처치 44초 |
| **골드 재굴림 정책**(active, 여유분 재굴림) | 재굴림 p50 10회 · 지출 1,900골드 → 처치 1,248(무지출 1,238), 도감 **15 = 무지출과 동일**, 잔액 23,896 |

- **순수 방치의 정지 상태를 성장으로 보고하지 않는다.** 동료 0 + 입력 0이면 이 게임은 30분 동안 아무 일도 하지 않는다.
  다만 이 상태는 데스크톱 실사용과 다르다 — 이 게임의 공격은 전역 입력 훅(`src/main/globalInput.ts`)에서 오므로
  "업무 중 타이핑"은 곧 active 입력이다. 진짜 0입력은 "사람이 자리에 없음"을 뜻한다. 그 판단 근거는 코드 경로이고,
  실제로 업무 타이핑이 얼마나 공격으로 들어오는지는 **미확인(PENDING)**.

30분 중 게이지가 켜져 있는 시간은 **99.2%** (active/intermittent 1,785/1,800초, idle p50 1,786초).
꺼져 있는 유일한 상태가 "오퍼 준비 완료"이고 그건 30분에 15초(0.8%)뿐이다.
이제 실질적인 행동 유도는 게이지가 아니라 `REBIRTH READY`(노랑 텍스트)와 **게이지의 소멸**이다.
게이지 자체는 배경 chrome에 가깝다. 다만 40×3, 필드의 0.5%, 고정 위치, 교집합 0이라 **가림/소음 피해는 관측되지 않았다**.
판정: 실패 아님. 다음 라운드에서 "off가 신호"라는 반전이 사람에게 읽히는지만 확인 필요.

**P2b (minor, 신규) — 같은 자리·같은 크기의 바가 색으로만 두 의미를 구분한다.**
파랑=휴식 잔여(감소), 청록=Lv.12까지의 진행(증가). 두 모드 사이에 라벨이 없고, 게다가
`drawLevelHud`의 **XP 바도 청록 40×4**다. 화면에 청록 진행 바가 두 개(좌상단=환생 해금까지, 머리 위=다음 레벨까지)
비슷한 크기로 공존한다. 코드상 의미는 명확하지만 사람이 구분하는지는 **PENDING**.

**P2c (minor, 신규) — 유예(defer) 중에는 게이지가 100% 청록으로 멈춘다.**
`heroDefer` 직후 `deferRemainingMs>0`이고 `restRemainingMs=0`이므로 `resting=false`,
비율은 `level/12 ≥ 1`로 클램프되어 **꽉 찬 정적 바**가 최대 30초 유지된다(카운트다운 없음).
"곧 온다"는 뜻으로는 맞지만 남은 시간 정보는 없다. 시뮬레이션 정책이 항상 즉시 수락이라 측정 표에는 나타나지 않는다(코드 판독).

**초반(Lv.1) 오해 여부 — 문제 없음으로 판정.** Lv.1에서 청록 바는 1/12≈8%(채움 3px)로 시작해
첫 처치부터 눈에 띄게 늘어난다. "빈 바가 켜져 있는데 아무 일도 안 일어난다"는 상태가 아니다.
온보딩 120초 동안 active는 게이지가 계속 커지다가 78초쯤 첫 오퍼에서 사라진다(= 보상 신호).

**정지 구간(무표시의 후속 지표)**: 게이지가 켜져 있어도 **채움 폭이 전혀 변하지 않는 최장 연속**을 새로 쟀다.
active/intermittent **max 16초**, idle **p50 41 / p90 324 / max 548초(seed 68, Lv.10, 32/38px)**,
seed 91은 **521초(Lv.9)**. 즉 최악 idle에서도 이전의 "25분 무표시"가 "최대 9분마다 한 칸 전진하는 게이지"로 바뀌었다.
정보량이 0에서 양수가 되었으나, idle 최악 구간의 **체감 진행 속도 자체는 그대로**다(U3의 근본 원인은 스폰/성장이지 표시가 아니다).

### 4. simulated / human 구분

- **simulated (이 문서에서 확정)**: blind 0초, 게이지 상시 99.2%, 픽셀 예산·교집합 0, 게이트 131 통과, 수치 무변경(deep-equal).
- **human PENDING (모델이 대신 판정하지 않음)**:
  1. 99.2% 상시 게이지가 "안심"인지 "무시하게 되는 장식"인지.
  2. 파랑↔청록 모드 전환과 머리 위 XP 바의 혼동 여부.
  3. 게이지가 **사라지는 것**이 행동 유도로 읽히는지(현재 유일한 off 신호).
  4. idle 9분간 한 칸만 움직이는 게이지가 "느리지만 살아있다"로 읽히는지 "멈췄다"로 읽히는지.
  5. 유예 30초 동안의 꽉 찬 정적 바가 오해를 주는지.
  6. 앞선 섹션 7의 기존 PENDING 6항목은 그대로 유효하다.
