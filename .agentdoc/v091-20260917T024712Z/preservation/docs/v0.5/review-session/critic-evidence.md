## 선택 의미와 작업 방해

같은 raw20/stack0에서 동등한 공격력 동료5명이 모두 불이면 불 element 영웅은 총+40%,
party 영웅은+20%다. 불 동료가1명뿐인 혼합이면 element는 총+8%, party는+20%다.
따라서 레어/높은 단계 하나가 모든 파티에서 최고가 되는 구조는 아니다. 반복 중첩으로 특정
보유 영웅의 수치가 높아질 수 있지만 모든 외형에 같은 규칙을 적용하고 무료 재장착을 유지한다.
후반의 실제 선택 다양성과 영웅 피해 기여도는 표본/사람 관찰 없이 좋다고 단정하지 않는다.

세 선택지는 ID와 속성이 다르고 새 레어의 장비·무기 외곽을 따로 그리는 계약이다. 단순 팔레트
복제품으로50종을 채울 수 없다. 단색 실루엣과 기존 앵커/프레임 테스트가 구현 증거가 된다.

기존 메뉴 안에 패널만 더하고 자동 선택 모달/포커스를 만들지 않는다. 보류는 레벨/동료/골드를
초기화하지 않으며120초 환생 휴식과30초 보류 시간을 구분한다. autosave가 이름 편집과 도감
펼침을 파괴하지 않아야 한다.420pt 및 더 좁은 창의 가로 넘침은 실제 CSS/DOM 확인 대상으로 남는다.

## 판단과 실행 시 지켜야 할 세부 사항

blocker0 / major0. 요구8개는 수식·사건·조건·저장·UI 경계가 정해져 있어 구현 진행에 동의한다.
상위 설계는 h52의 h01×2가 초안의 검사 계열×2를 대체한다고 명시하므로 혼합 해석하지 않는다.
내부 필드 시간은 새벽0–5분이므로 `새벽+플레이5분`인 mistaxolotl은 최초20분부터 가능하다.
도감은 이 AND를 그대로 보여주어5분 직후에 나올 것처럼 말하지 않아야 한다.

원자 파일 저장이 실패했는데도 영구 PvP 통계를 보존했다고 주장하면 안 된다. main-origin 동기화,
동일 match 동시 성공 방어, 저장 성공 뒤 재시작의 절대 카운터 복구는 통합 테스트에서 필수다.
기존 코드의 net/identity store가 실패 boolean을 무시하는 점은 이번 구현에서 이 경로를 검토할
근거이며, 현재 설계가 요구하는 원자 보존 자체를 만족했다고 간주하지 않는다.

balance의 seeds1–100과 사전 구간, playtester의5/15/30분×3프로필을 통과해야 시뮬레이션
리뷰가 끝난다. native smoke/package/실서버와 사람 재미/외형/업무 방해는 별도 PENDING이다.
