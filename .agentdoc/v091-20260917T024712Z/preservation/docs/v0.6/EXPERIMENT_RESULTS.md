# DesMon v0.6 실험 결과

**최종 0.6.0 소스 측정 결과: 초과 포획 보류 기능을 v0.6 범위에서 조건부 제외한다.** 같은 10분 방문 일정의 기존 관리와 비교했을 때, 모든 seed·5속성에서 악화가 없어야 한다는 사전 조건과 seed별 클릭·후보 손실 조건을 충족하지 못했다. V06-07/08은 이 결과를 근거로 제외하며 포획 상태는 현재 방출 방식으로 유지한다. 훈련 가격·피버 수치·포획률·창고 용량도 변경하지 않는다.

앱 버전 **0.6.0**과 아래 소스·평가 도구 지문을 동결한 뒤 포획·피버·신규 idle 실험과 canonical 100-seed 측정을 실제로 다시 실행했다. 두 명령 모두 종료 코드 0이다. 이 문서는 최종 소스의 수치 검증이며, 실제 Electron 9조합·UI journey·4역 감사·패키지와 사람 관찰의 완료 판정을 대신하지 않는다. 사람 관찰은 `PENDING`이다.

## 실행 조건

포획 실험은 각 조합에서 seed 1..100, 고정된 fresh 또는 full-roster-fixed 세이브, 30분간 초당 2입력 후 tick(1000), 구매 없음이다. full-roster-fixed는 기준 엔진에서 921초·환생 8회 뒤 처음 동료 30마리에 도달한 저장이며 모든 seed에 같은 bytes를 제공했다.

단계 1은 환생 준비 즉시 첫 후보를 선택하고 동료 관리는 별도 방문한다. 단계 2는 환생과 동료 관리를 같은 방문에 묶는다. 관리 없음은 단계 2의 환생 선택도 0회다. 120/600초의 양의 배수에서 방문하고 마지막 1,800초 방문까지 처리한 후 측정한다.

기존 관리와 보류안 모두 방문 때 30마리가 있으면 production companionPower가 가장 작은 동료(동률은 저장 순서)를 명시적으로 희생하여 한 자리만 비운다. 보류안은 첫 초과 포획을 고정하고 후속 초과 포획을 기존 규칙으로 방출한다. 방문에서 빈칸에 후보를 더한 5속성 합이 관리 전보다 모든 속성에서 같거나 크고 하나 이상 커질 때 수락하며, 아니면 거절하여 현재 방출 홀짝으로 정산한다. 기존 동료를 자동 교체하지 않는다.

클릭은 메뉴 열기·동료 탭·닫기 각 1, 희생·보류 수락/거절 각 1이다. 단계 1의 즉시 환생 방문은 열기·영웅 탭·제안·선택·닫기 5클릭, 단계 2에서는 같은 방문에 영웅 탭·제안·선택 3클릭을 더한다. 이는 사전에 고정한 최소 스크립트 조작 수이며 사람이 카드나 안내를 읽는 시간은 포함하지 않는다.

실험용 vm이 현재 compiled production engine의 포획 분기 한 곳만 계측한다. 피해·RNG·포획 추첨·영웅·희생·전투 시간은 실제 엔진을 실행했다. no-op 계측과 원본은 seed 71의 180초·포획 추첨 5회에서 이벤트와 저장이 같았다. 별도 유사 게임 모델이나 기본 게임의 보류 구현은 사용하지 않았다.

## 영혼과 보류의 교환 비용

10,800개 원시 행에서 `포획=새 획득+최종 방출+현재 보류`, `종료 영혼=초기 영혼+환생 영혼 변화+명시 희생 영혼+방출 영혼`이 일치한다. 측정기는 기존 방출 횟수 홀짝, 실제 골드 수입·잔액, 방문/클릭 내역도 검사했다. 초기 full fixture 영혼 62개는 새 수입으로 계산하지 않았다.

`soulDelaySeconds`는 **보류 포획 단위의 누적 대기초**다. 결국 수락한 후보와 방출 홀짝 때문에 지금 영혼 지급량이 0인 보류도 포함하며, 실제 미지급 영혼 수×시간을 뜻하지 않는다. 지급 가능 영혼은 `soulsPending`, 미정산 포획 단위는 `pendingReleaseUnits`로 별도 남겼다.

자동 소유 동료 삭제·중복 정산·강제 창은 실험 adapter의 원시 지표에서 모두 0이다. 이는 후보 저장/UI를 출시했다는 검증이 아니다. 실제 보류 기능은 구현하지 않았으므로 `candidateLossOnReload`, 원자적 저장 실패 복구, stale 교체 대상, 서버 업로드 제외를 포함한 V06-07/08의 제품 검사는 `PENDING / 조건부 제외`다. 기존 기능의 저장·재개 검사는 별도 최종 검증에서 수행한다.

## 순수 신규 idle과 해석 한계

별도 fresh idle 100 seed의 5/15/30분 모두 입력·메뉴·처치·동료·골드가 0이고 Lv.1이다. 첫 보상과 첫 포획은 각 체크포인트에서 100/100 미도달로 남겼다. 진행 0을 자동 성장 성공으로 계산하지 않는다. 기존 canonical의 warm-idle은 처음 120초 입력과 즉시 환생을 포함하므로 이 결과와 분리한다.

이 측정은 주입 시간의 production core 실행이다. 실제 Electron 9개 독립 실행, 새 UI journey, 접근성·전역 입력·운영 PvP나 사람의 재미·업무 방해를 대신하지 않는다. 사람 관찰 5명×30분은 `PENDING`이며 AI 의견으로 채우지 않았다. 프로토콜의 조건·seed·시작 저장·채택 기준은 결과에 맞추어 변경하지 않았다.
