## 해석 범위

전체 프로세스의 working set 합계는 공유 페이지를 중복 계산할 수 있다. 경계 시점의 메모리 압력·압축·스왑·프로세스 상태를 기록하지만, 사용자 작업과 OS의 순간적인 회수·GC 원인을 모두 통제하거나 분리하지 못한다. 기준선부터 실행하는 단일 순차 블록이므로 시간 순서 영향도 남는다. 이 검증은 등록된 회귀 예산의 확인이며 배터리 수명이나 인과관계의 입증은 아니다.

## 독립 검토의 조건 위반 발견

`reviews/performance-result-review.json`은 전체 3,593개 표본의 산식을 독립 재계산해 수치 일치를 확인했지만, 이전 attempt02의 중단된 idle 앱 PID 72888과 세 helper가 matched03 전체에 걸쳐 살아 있었음을 확인했다. 고유 userData `desmon-v10-perf-Yue7H3`와 시작 시각이 이전 로그에 일치하며, 여섯 경계 스냅샷에 모두 남아 있었다. 사용자 앱이 아니라 에이전트가 실행했던 앱이다.

따라서 no-concurrent-agent-Electron 및 이전 앱 계보 종료 조건을 위반했다. 기존 자동 AC가 이 조건을 검사하지 못한 결함도 수정한다. Root가 소유권을 재확인하고 부모 앱에만 SIGTERM을 보내 네 프로세스가 모두 종료됐음을 확인했다(`evidence/orphan-cleanup-matched03.json`). 관측기 종료 처리와 검증 게이트를 수정하기 전 결과를 다시 실행하거나 승인하지 않는다.

## 관측기 정리 수정과 다음 검증

2026-09-18 04:20 KST: 관측 중단은 관측기 PID에 전달하고, 관측기가 자기 앱·하위 프로세스 정리를 끝낸 뒤 부모가 `close`를 기다리도록 수정했다. 시작 전·inspector 대기·관측 중·기록 실패·큐 중단의 실제 macOS 5건에서 잔존 앱은 없었으며, 이 5건은 취소되었으므로 성능 통과 자료로 사용하지 않는다. 이전 버전과 후보의 정상 종료도 각각 실제 30초 동안 확인했다.

새 `.harness/v10/performance-isolation.mjs REGISTRATION_JSON METHOD_REVIEW_JSON`은 사전등록된 기준선 활동30 → 기준선 방치30 → 후보 활동30 → 후보 방치30 → 혼합180분을 한 번 실행한다. 각 경계에 DesMon 앱·helper가 없어야 하고, 실행 중 5초 간격 프로세스 기록을 남긴다. 최종 검증은 전체 기록 간격, PID·시작 시각·앱 경로·임시 저장 경로, 측정한 Browser PID, 정리 완료를 재검사한다. 수치 통과만으로 완료 처리하지 않으며, 완료 후 독립 결과 검토도 필수다.

5초보다 짧게 생겼다 사라지는 프로세스나 다른 이름의 일반 Node·빌드 부하는 이 기록만으로 배제할 수 없다. 관측 블록에서는 에이전트의 다른 앱·테스트·빌드·시뮬레이션 실행을 금지하고 저널에 기록한다. 일반 사용자 앱은 통제하거나 종료하지 않는다. 사용자 DesMon이 발견돼도 관측을 중단하며 강제로 종료하지 않는다.
