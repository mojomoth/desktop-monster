무결성 검산은 실제 생산·컴파일 export의21키, 각실험 S/E, 공식 프로토콜·실행 등록, source/evaluator/build 아카이브, 보고서·manifest·180개 seed JSON의 hash/binding,114테스트 로그까지 포함한다. 17개 고유 아카이브에 중복·위험·비정규 파일 경로가 없고, 각 runs 폴더는manifest1개+등록 seed20개만 포함한다. source tar는root-relative이고 평가digest는.harness/v7와공식protocol만 포함하며 추가보존DESIGN은 별도다. 모든 실제 소스 아카이브에서 control-l17 대비 달라진 파일은 src/core/progression.ts 하나뿐이며 테스트 등 나머지 바이트는 동일하다.

8개 모두 지정4파일114/114 테스트exit0, 9개 보고서 각각 structural verify exit0이었다. 7개 선별 실패와1153의12시간 목표 실패는 각exit1 원본·로그·raw를 그대로 보존했다. 대조5개의100개 raw는 Round06 동일 seed/정책/fixture 결과와 정확히 같다. 별도 Python 검산으로7개 첫 사건과h70의 전체/조건부 통계도 재확인했다. 각checkpoint의 골드 유입−지출=잔액, 안전정수와 정확한bigint 피해/파티힘, 실제선택ID 개수도 확인했다. 준비 시점의 AC/gates/readiness 해시와 각변형114테스트를 구분하며, 당시 결과를 현재 트리 전체의 새 인증으로 표시하지 않는다.

모든8개 완료 후에만 적용한 등록 순위는 두 목표 통과안의 정수100ms tuple(|firstp50−3150|,|h70p50−36000|,firstp90,ID)이다. 이번 통과안은0개이므로 passingRanking=[],proposedExperiment=null이며 자동채택하지 않았다. 후속 탐색은 목표·분모를 유지한 새 사전등록이 필요하고, 이 분석은 새 수치를 제안하거나 검증 데이터를 튜닝에 사용하지 않았다.

이 결과는 탐색 분석 완료이며 최종 audit.mjs 수행이나 제품 출시 검증이 아니다. 최종0.7.0 소스의 등록AC/canonical gates, 정책별100seed×12시간, 실제5/15/30분×3프로필과 별도180분active/10분마다메뉴선택, 네역할독립audit·smoke·실제패키지·출시전고레벨서버호환은 별도다. 사람 관찰을 새로 수행하지 않았으므로 humanChecks=PENDING을 유지한다.
