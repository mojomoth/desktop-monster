# v7 하네스 준비 실행 결과

하네스 준비의 모든 등록 AC가 통과했다. 제품 v0.7 구현은 미착수이며, 하네스 준비 완료와 별개다. 최종 작업 상태는 [loop.json](../loop.json)의 H07-01을 확인한다.

검증: **하네스 98개 테스트**, 정확한 `npm test && npm run lint && npm run typecheck` **exit 0**(제품 테스트 776개), 엄격한 baseline 단계 검증, 기존 파일 179개 보존 검증을 실행했다. 명령과 로그 해시는 [completed-checks.json](completed-checks.json)에 있다.

앱 **0.6.0**, `.harness/CURRENT=v3`, 기존 npm 명령과 제품 소스는 시작/종료에 동일하다. 기존 데모 스크립트 4개의 lint 오류 64개는 원본을 백업한 뒤 동작을 유지하며 수정했다. [수정 근거](../reviews/preexisting-lint-repair.md)와 [검토 가능한 diff](../reviews/preexisting-lint-repair.diff)를 보관했다.

## 현재 v0.6 기준선

실제 엔진의 결정적 시뮬레이션으로 seed 1–100 각각 12시간을 측정했다. 신규 게임·100ms tick·균등 초당 2입력·골드 미사용·동료 무관리·준비 즉시 첫 환생 후보 선택이다. 총입력은 seed당 86,400회이며 골드 사용은 0이다. 4개 worker의 시뮬레이션 계산 시간은 약 412.4초였으며, 실제 Electron이나 사람의 1,200시간 플레이가 아니다.

| 첫 환생 사건 | p10 | p50 | p90 | 미도달 |
| --- | ---: | ---: | ---: | ---: |
| 준비 | 76초 | 78.5초 | 80.5초 | 0/100 |
| 제안 열기 | 76초 | 78.5초 | 80.5초 | 0/100 |
| 선택 성공 | 76초 | 78.5초 | 80.5초 | 0/100 |

성공 범위는 72–82.5초다. 100/100이 90분 안에 성공했지만, 중앙값 78.5초는 v0.7 목표 45–60분을 충족하지 않는다. 즉시 선택 정책이므로 준비·열기·성공 시각이 같다. 미도달 표본을 제외하여 통과시킨 결과가 아니다.

| --- | ---: | ---: | ---: | --- |
| 5분 | 2 | 2 | 81 | 30 / 112 |
| 15분 | 7 | 7 | 122 | 58 / 124 |

전체 카탈로그는 영웅 70개·몬스터 135종이다. 이 기준 정책의 모든 seed에서 2시간부터 12시간 사이 새 해금 자격·선택 영웅·처치 몬스터 종의 증가가 0이었다. 환생은 계속되지만 새 콘텐츠 도달은 정체되어 있다. 이는 해당 정책의 관측이며, 다른 골드·동료 관리 정책에서도 모든 콘텐츠가 소진된다는 뜻은 아니다.

8–12시간 마지막 신규 해금 목표는 아직 구체적인 milestone ID를 등록하지 않아 미평가다(`registered:false`, 집계 PASS로 처리하지 않음). 후속 V07-01에서 ID와 후보 수치를 등록한 뒤 새 프로토콜로 비교한다. 초기 해금은 1초 정기 관측과 관련 사건 직후 100ms 경계에서 관측하며, 한 엔진 호출 내부의 중간 상태나 순수 시간 조건의 짧은 창에 대한 한계는 원시 보고서의 method에 명시했다.

원시 기록·집계·지문: [baseline.json](baseline.json). 재집계용 표: [baseline-checkpoints.csv](baseline-checkpoints.csv). 실행 조건·환경·아카이브 SHA: [baseline-execution.json](baseline-execution.json). 중단된 attempt01/02는 원본 그대로 남겼으며 최종 표본에 섞지 않았다.
