# Final 0.7 wrappers — independent static Critic review

Reviewer: `/root/critic`. Scope: both prepared wrappers in full and their existing develop/measure/evidence helpers. No script, test, build, engine, measurement or Native execution was performed; no partial validation output was read. This is a wrapper preflight review, not a new fun decision or result audit. Only this new report is written.

Two prelaunch guard gaps remain. These are static counterexamples, **not claims that the currently frozen source or tests have changed**.

1. **Final review is not bound to V05/validation readiness.** `sessions/final-v070-fresh-verification.py:8–9,19–24` binds V01–04 verification to the completed final fun's S/E, but its final V05 loop at lines 45–47 only checks subprocess success. `final-v070-validation.py:35–45` compares the V05 checks with each other and live S/E, without comparing them to a completed final fun session. Consequently, if source/evaluation changes after V04 verification and the three V05 checks run successfully on the changed input, both wrappers can launch final100 against an input different from the completed design review. `develop.mjs` dependency readiness uses task statuses, so it does not supply this missing prelaunch equality. Minimum condition: before measurement, verify the completed final fun and require its source/evaluation digests to equal all selected V05 check digests and live digests. If they differ, stop for fresh ordered review/affected checks; do not treat the previously completed review as current. Binding V05 at the end of the fresh-check wrapper also catches drift earlier.

2. **Owned-file freshness is omitted before expensive validation.** `final-v070-validation.py:40–45` verifies check exits, log hashes, start/end S/E and live S/E, but never checks `filesHash`/`endedFilesHash` against current `task.files`. `evidence.mjs:sourceDigest` covers src/static/package/tsconfig; repository tests are excluded, and `evaluationDigest` covers the v7 harness and official protocol. A change to owned `tests/balance.test.ts` after V05 checks therefore leaves S/E unchanged, passes this precheck, and can be archived beside stale test-readiness evidence. Minimum condition: use the existing `develop.mjs` fileManifest for V05 task.files and compare each selected check's start/end/current manifest before output creation/measurement. This is **not** an eventual verified-status bypass: `develop.mjs:113–119` already rejects such a mismatch during task verification. The missing guard permits unnecessary final100 execution and a source archive whose owned tests differ from those that ran.

The rest of the bounded execution contract is coherent:

- Fresh verification calls only registered develop commands. It writes each session with exclusive `open('x')`, stops on nonzero, and delegates actual verification to develop, which checks current file manifests, registered artifact manifests and all retained check-log hashes. Its latest-result map does not delete earlier failed checks. V01's already-run protocol/harness/gates are reused only from this current final attempt and must match the completed review; the design AC is newly executed. This is consistent with the stated setup for this one-shot wrapper, not permission to reuse historical 0.6 checks.
- Validation requires a new output directory, report and `.runs` path, the exact adopted official protocol SHA, candidate10450, candidate phase/V05 running, and package0.7. It uses fresh official validation seeds; the completed report must contain exactly1–100 and the selected experiment/S/E. No explicit seed override, exploration mix, old output resume or reused report is present. The existing measure CLI separately checks official protocol, production build/export/binding and source/evaluation stability, and verify rechecks build/export provenance.
- Source/evaluator archives use relative names and refuse an existing archive. Command logs use exclusive creation. Nonzero command results are appended to execution.json with their log hashes before stopping; report/raw files and earlier failures are retained. A measure exit1 is deliberately allowed so a target failure can still receive structural verification and a complete archive. `VALIDATION_COMPLETE` consequently means completed measurement/recording, **not targets passed**; `targets` and the recorded measure exit must remain visible, and registered `verify --phase candidate` is still required before V05 verification. This wrapper does not mark V05 verified.
- The final endedAt is written after the compiled archive. Interrupted execution lacks that final marker and cannot be treated as completed. These wrappers are one-shot: an existing session/output causes rejection rather than overwriting history; interrupted follow-up must preserve original artifacts and use an explicitly chosen recovery path.
